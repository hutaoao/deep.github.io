## 一句话概括

自定义组件可以理解成一个**封闭的盒子**：数据只认两个入口（`properties` 属性、`slot` 插槽），结果只走一个出口（`triggerEvent` 事件）。

面试问组件，表面在问 `Component` 怎么写，实际在问三件事：

1. **时序**——`created`、`attached`、`ready` 到底差在哪，为什么你在 `created` 里 `setData` 没反应；
2. **数据流向**——`properties` 和 `data` 是两套东西，混着改一定会出诡异 bug；
3. **边界**——属性、slot、外部样式类都是**外部输入**，和接口返回的数据一样不可信。

前两条决定组件好不好维护，第三条决定它安不安全。这篇把两边都讲透。

## 核心知识点

### 1. 生命周期：`created` 不能 `setData`，`ready` 别乱用

先看官方定义：

| 生命周期 | 触发时机 | 能不能 `setData` |
| --- | --- | --- |
| `created` | 组件实例刚被创建，`this.data` 就是构造器里定义的初始值 | **不能** |
| `attached` | 组件完全初始化完毕、**进入页面节点树**后 | 能，绝大多数初始化都放这儿 |
| `ready` | 渲染线程初始化完成（布局完成） | 能 |
| `moved` | 组件实例被移到节点树另一个位置 | 能 |
| `detached` | 组件被移出节点树 | 能，但一般用来清理 |
| `error` | 组件方法抛错时（2.4.1 起） | —— |

所以第一个高频坑：`created` 里 `setData` 无效，官方原文是「**此时还不能调用 `setData`**，通常情况下，这个生命周期只应该用于给组件 `this` 添加一些自定义属性字段」。

第二个坑更隐蔽：**`ready` 不可靠**。官方专门写了警告：

> 取决于渲染线程的繁忙情况，`ready` 回调可能会非常晚，并可能在组件被移除后才回调。绝大多数情况下，应使用 `attached` 代替。

而且 `ready` 有三种可能的触发顺序：

1. `attached` 之后 `ready`；
2. `attached` 没触发，只有 `ready`；
3. `attached` → `detached` 都执行完了，`ready` 才来。

第 3 种意味着你在 `ready` 里拿节点尺寸，可能拿到的是「组件已经被销毁」的结果——这也是「量元素宽高偶尔拿到 0」的经典原因。

写法上，生命周期放在 `lifetimes` 字段里（2.2.3 起，**优先级最高**），旧式写法只用于兼容老基础库：

```js
Component({
  lifetimes: {
    created() {
      this._timer = null          // ✅ 只挂自定义字段
      // this.setData({ a: 1 })   // ❌ 无效，此时还不能 setData
    },
    attached() {
      this.setData({ loading: true })   // ✅ 初始化放这里
      this._timer = setInterval(this.poll, 3000)
    },
    detached() {
      clearInterval(this._timer)        // ✅ 一定要清，否则页面来回进出会内存泄漏
    },
  },
})
```

还有一组 `pageLifetimes`（2.2.3 起），让组件感知所在页面的 `show` / `hide` / `resize` / `routeDone`。**注意自定义 tabBar 的 `pageLifetimes` 不会触发**，这个细节能答出来很加分。

### 2. `properties` 和 `data`：一个是入参，一个是内部状态

两者在 `this.data` 里是合并的，所以很容易误以为是一回事。区别在于**归属**：

```js
Component({
  properties: { value: { type: Number, value: 0 } },   // 外部给的
  data: { innerValue: 0 },                              // 自己管的
})
```

为什么不能直接 `setData` 改 `properties`？因为父组件的数据源还在，下一次父组件 `setData` 或者重渲染，值会被**覆盖回去**，表现就是「改了一下又弹回来」或者「闪一下」。更麻烦的是组件内部状态和外部入参不一致，排查时根本不知道该信谁。

正确做法：**属性只读，派生值算到 `data` 里。**

```js
// ❌ 直接改属性，父组件一刷新就被覆盖
this.setData({ value: this.data.value + 1 })

// ✅ 属性只读，内部状态自己维护
this.setData({ innerValue: this.data.value + 1 })
```

顺带一个类型坑：`properties` 声明了 `type: Number`，父组件传字符串 `"12"` 会被转成 `12`；传 `undefined` 会用默认值；传了类型不匹配又转不了的值，会落到默认值上，而**不会报错**。所以「我明明传了值，组件里却是默认值」——先查类型。

### 3. `observers`：监听的是「被 `setData` 涉及的字段」，不是「变化的字段」

数据监听器 2.6.1 起支持，语法比属性上的 `observer` 强得多：

```js
Component({
  data: { numberA: 0, numberB: 0, sum: 0 },
  observers: {
    'numberA, numberB'(a, b) {          // 监听多个
      this.setData({ sum: a + b })
    },
    'arr[12]'(val) { /* ... */ },        // 监听数组下标
    'form.user.**'(user) { /* ... */ },  // 监听整个子树
  },
})
```

三个必须记住的规则：

1. **只要字段被 `setData` 涉及就触发，哪怕值没变。** 官方原话：「数据监听器监听的是 `setData` 涉及到的数据字段，而非变化的数据字段。」所以你 `setData({ list: this.data.list })` 也会触发——别在监听器里做重活。
2. **一次 `setData` 最多触发每个监听器一次**，不用担心多字段批量更新时被调 N 次。
3. **在监听器里 `setData` 同一个被监听的字段，可能死循环。**

还有一个特别容易答错的细节：官方明确说「在数据监听器中调用 `setData` 后，数据变更并不会**同步**应用到 WXML 模板上」，效果等同于 `updateData`。也就是说监听器里算出来的 `sum`，是在这一轮更新之后才进模板的。

`**` 通配符能监听全部 `setData`，但等于给每次更新都挂一个回调，纯调试用，别上生产。

### 4. `behaviors`：官方版 mixin，但覆盖规则比 mixin 复杂

`behaviors` 用来抽组件间的公共逻辑（官方类比 mixins / traits）。难的不是怎么用，是**同名冲突时谁赢**，这块答清楚了面试官基本就满意了：

| 冲突类型 | 规则 |
| --- | --- |
| 属性 / 方法 | 组件自身 > behavior；靠后的 behavior > 靠前的；引用者 > 被引用者 |
| `data` 同名字段 | 都是对象则**合并**；否则按上面同样的覆盖顺序 |
| 生命周期 / `observers` / `externalClasses` | **组合执行，不覆盖**：靠前的 behavior → 靠后的 behavior → 组件自身；被引用的 behavior 优先于引用者 |

注意第三行：生命周期是**全部执行**的，不像 mixin 那样后者覆盖前者。这既是优点（逻辑不会被悄悄吃掉），也是坑（两个 behavior 都写了 `attached` 发请求，就会发两次）。

还有一条很细的规则：**同一个 behavior 被一个组件多次引用时，`Definition` 形式的不会重复执行，`Chaining` 形式会重复执行。** 这个通常不用主动说，被追问「重复引用会怎样」时能答出来就行。

内置 behaviors 也值得记两个：

- `wx://form-field`：让自定义组件表现得像表单控件，`form` 组件的 `submit` 事件能拿到它的字段名和值。
- `wx://form-field-group`（2.10.2 起）：让 `form` 能识别到这个组件内部的所有表单控件。

做表单类组件时不用自己造轮子，直接用这两个。

### 5. 两个被忽略的开关：纯数据字段和 `virtualHost`

**纯数据字段**：只存在 `this.data` 里、不参与任何界面渲染的字段，标记出来能减少更新时的数据传输量。

```js
Component({
  options: { pureDataPattern: /^_/ },   // 下划线开头的都是纯数据字段
  data: { _cache: {}, visible: false },
})
```

两个注意点：2.10.1 起可以在组件 JSON 里写 `"pureDataPattern": "^_"`（字符串形式）；**纯数据字段如果是属性，它自己的 `observer` 永远不会触发**，要监听变化只能用 `observers`。

**`virtualHost`**（基础库 **2.11.2** 起）：默认情况下自定义组件本身那个节点是个「普通节点」，能接 `class`、`style`、flex 布局。但有时你希望**这个节点不存在**，让组件内部第一层节点直接参与父级 flex 布局：

```js
Component({
  options: { virtualHost: true },
  properties: { style: { type: String } },  // style 要自己声明成属性才能拿到
  externalClasses: ['class'],               // class 要声明成外部样式类才能透传
})
```

开了之后，组件节点上的 `class`、`style`、动画**全部失效**，只能靠上面那两行手动接回来。这是做「布局容器类组件」时的必备开关，不然外面套一层节点 flex 就断了。

### 6. 第一道安全边界：`properties` 是不可信输入

组件属性和接口返回的数据没有本质区别——**它们都可能来自用户**。链路上是这样传的：

用户输入 → 页面 `data` → 组件 `properties` → 组件内部逻辑

所以组件里对属性做任何「拼」的操作都要小心：

```js
// ❌ 属性直接拼进 URL：外部传个 ../ 或完整域名就能改请求目标
const url = `${this.data.baseUrl}/detail?id=${this.data.id}`

// ✅ 白名单校验 + 编码
if (!/^\d+$/.test(this.data.id)) return
wx.request({ url: `${API_HOST}/detail?id=${encodeURIComponent(this.data.id)}` })
```

更常见的是 `rich-text`：

```js
// ❌ 直接把外部 HTML 字符串塞进 nodes
this.setData({ nodes: this.data.articleHtml })
```

`rich-text` 的 `nodes` 支持传 HTML 字符串，会解析成受支持的节点。它虽然不会执行 `<script>`，但外部内容可以塞进大量节点、外链图片、诱导性文案——**内容安全和性能两头都失控**。正确姿势是：服务端做好内容审核（`msgSecCheck`），前端只渲染可信来源，并且限制节点数量。

一句话记：**组件的属性不是配置，是入参；入参要校验。**

### 7. 第二道边界：`slot` 的内容不受组件控制

很多人以为 `slot` 的内容归组件管，其实完全相反：

- `slot` 里的 WXML 是在**父组件的作用域**编译的，数据绑定走父组件的 `data`；
- 样式也归父组件管，组件内部的 `wxss` 管不到 `slot` 里的节点（除非显式改样式隔离）。

这意味着：**组件没办法「过滤」使用者塞进来的内容**。所以像「卡片组件里一段富文本」这种需求，别指望在组件内部兜底，必须在数据进入组件前就处理好。

顺带说清 `externalClasses` 的边界（1.9.90 起，2.7.1 起支持传多个类）：外部样式类是让父级能改组件内部样式，本质是**主动开了一个口子**。官方有一条警告值得背：

> 在同一个节点上使用普通样式类和外部样式类时，两个类的优先级是未定义的，因此最好避免这种情况。

所以别在组件内部给同一个节点既写死 `class="title"` 又挂 `externalClasses`，样式会变成玄学。

### 8. 第三道边界：越权和敏感数据，前端挡不住

这部分是官方《安全指引》的原话，面试答这几条就够了。

**五条总体原则：**

1. **互不信任**：不要信任用户提交的数据，包括第三方系统提供的数据，必要的数据校验必须放在**后台**。
2. **最小权限**：代码、模块只拥有完成任务所需的最小权限。
3. **禁止明文保存用户敏感数据**。
4. 小程序代码「**可被外部获取及进行反混淆**」，重要业务逻辑应放在后台或云函数。
5. 后台接口调用以及云函数调用，**必须进行有效的身份鉴权**。

第 4 条是最容易被忽略的：**小程序代码不是二进制，混淆只是提高成本，不是安全边界。** 所以 AppSecret、加密密钥这类东西一旦写进前端，就等于公开。

**两类越权，必须能区分：**

| 类型 | 定义 | 例子 |
| --- | --- | --- |
| 平行越权 | 同角色之间的越权 | `userinfo?id=A1` 没校验，改成 `A2` 就能读别人的 |
| 垂直越权 | 不同角色之间的越权 | 普通用户直接请求管理员接口 `getAllUserInfo` |

官方明确点名了一个错误做法：「**鉴权逻辑应放在后台进行，不应在小程序前端以隐藏页面、隐藏按钮等方式来代替。**」——按钮藏起来只是 UI，接口还是能被直接调。

**敏感信息不能怎么存？** 官方列举：不应以「明文、注释、可逆的编码方式（如 base64）、不安全散列函数（如 MD5、SHA1）」出现在小程序文件里。展示时还要脱敏：

| 类型 | 脱敏规则 |
| --- | --- |
| 手机号 | 位数≥10 显示前三位和后两位（`156******77`） |
| 身份证 | 只显示第一位和最后一位（`3*******************1`） |
| 银行卡 | 只显示最后 4 位（`************1234`） |

严重性也要说清楚：官方写明「如果小程序存在敏感信息泄露的问题，微信开放平台将有可能下架该小程序」。

**还有一个特别实在的坑：`.git` 目录被打进包里。** 用版本管理工具时 `.git` 目录如果被带到生产环境，就可能源码泄漏。检查方式很简单——上传前看一眼代码包体积是不是莫名其妙大了几 MB。

## 其实你每天都在用

- 组件里 `setInterval` 写在 `attached`、忘了在 `detached` 清，页面来回进出几次内存就上去了。
- 在 `ready` 里量元素宽高，偶尔拿到 0——因为渲染线程忙，回调来晚了。
- 父组件改了值，子组件「没更新」——十有八九是子组件内部 `setData` 改过 `properties`，或者类型不匹配落回了默认值。
- 拼团页的「活动已结束」只是按钮 `hidden` 了，接口照样能调，这就是拿 UI 当权限。
- 用户手机号在页面上显示全量 11 位，合规上就过不了。
- 你自己封装的 picker 组件，被页面的全局样式串了——`externalClasses` 优先级未定义导致的。
- 第三方组件库在 `attached` 里默默上报了一次埋点，你根本不知道。

## 常见误解（FAQ）

**❌ 误区1：「`created` 里可以发请求，反正也能拿到数据。」**
能发，但 `setData` 无效、`properties` 可能还没就绪，拿到结果也没法渲染。初始化统一放 `attached`。

**❌ 误区2：「`ready` 是『渲染完成』，量尺寸最准。」**
官方已经警告它可能非常晚、甚至在组件销毁后才回调。要量尺寸优先在 `attached` 之后配合 `wx.nextTick` 或 `SelectorQuery`，并处理「拿不到」的分支。

**❌ 误区3：「`observers` 只在值变化时触发。」**
它监听的是「被 `setData` 涉及的字段」，值没变也触发。想过滤真变化，用官方推荐的 `computed` 扩展或自己比对。

**❌ 误区4：「`behaviors` 就是 Vue 的 mixin，同名覆盖。」**
属性和方法是覆盖，但生命周期和 `observers` 是**组合执行**——两个 behavior 都写 `attached`，两个都会跑。混着理解会写出重复请求的 bug。

**❌ 误区5：「前端把按钮藏起来就算做了权限控制。」**
官方直接否了。前端隐藏只是体验，鉴权必须在后台或云函数里做，校验 `openid`、自定义登录态等。

**❌ 误区6：「AppSecret 放小程序里，混淆一下就安全了。」**
小程序代码可被获取和反混淆。密钥类信息只能放服务端，前端拿到的应该是一个短期的、可撤销的登录态。

**❌ 误区7：「`virtualHost` 只是少一层节点，没别的影响。」**
开了之后组件节点上的 `class` / `style` / 动画全部失效，必须把 `style` 声明成 `properties`、`class` 声明成 `externalClasses` 才能透传。

## 一句话总结

自定义组件是「数据从属性进来、事件出去」的封闭盒子；一旦你把盒子外面的东西——属性、slot、外部类、后台接口——当成可信的，安全边界就漏了。
