## 一句话概括

元服务 = **免安装、即用即走、≤10MB 的原子化应用**，通过扫码/搜索/碰一碰/卡片直达核心功能，核心哲学是"服务找人"而非"人找服务"。

## 核心知识点

### 1. 元服务 vs 传统 App——本质区别

```
传统 App：搜索 → 下载 → 安装 → 注册 → 找到功能 → 使用（7-10 步）
元服务：   扫码/搜索 → 直接使用 → 用完即走（2 步）

关键数据：华为统计显示，传统 App 从详情页到激活的转化率不足 30%
超过 40% 的用户在安装步骤就流失了
```

### 2. 元服务的四大入口

| 入口 | 场景 | 典型例子 |
|------|------|---------|
| 扫码 | 线下场景快速触达 | 扫码点餐、扫码骑车 |
| 搜索 | 服务发现 | 搜"酒店预订"直接出元服务 |
| 碰一碰 (NFC) | IoT 设备交互 | 碰烤箱→调出菜谱元服务 |
| 桌面卡片 | 持续感知 | 天气卡片、步数卡片 |

### 3. 元服务的核心约束

```typescript
// 元服务的技术限制（与完整 App 的差异）：
// ① 体积 ≤ 10MB（普通 App 典型 50MB+）
// ② 每个元服务只能有一个 UIAbility
// ③ 不支持多进程
// ④ 不允许后台常驻（功能够"原子"才合理）
// ⑤ 启动速度必须快（冷启动 < 2s，热启动 < 500ms）

// 设计原则：一个元服务 = 一个场景 = 一个核心任务
// ✅ 适合：点餐、购票、签到、查询余额、借充电宝
// ❌ 不适合：社交 App、大型游戏、复杂编辑器
```

### 4. 卡片（Form）——元服务的轻量 UI

```typescript
// 卡片是元服务在桌面的"窗口"，不需要打开应用就能看到信息
@Entry
@Component
struct WeatherForm {
  // 卡片构建函数
  build() {
    Column() {
      Text('28°').fontSize(32)
      Text('北京 · 晴').fontSize(14).fontColor('#999')
    }
    .width('100%').padding(12)
    .onClick(() => postCardAction(this, { action: 'router', abilityName: 'MainAbility' }))
  }
}
// 卡片特性：定时刷新、可交互跳转、即划即删
```

### 5. 元服务与 Ability 的关系

```dart
// Stage 模型中元服务的组织结构：
// 一个元服务 = 一个 Module
//   ├── 一个 UIAbility（唯一的入口 Ability）
//   │   └── 若干 Page
//   ├── 可选 FormExtension（桌面卡片）
//   └── 可选 ServiceExtension（后台任务，受限）
// 对比：完整 App 可以有多个 UIAbility + 更多 Extension 类型
```

## 其实你每天都在用

- **扫码点餐**：微信扫餐桌码 → 打开餐饮元服务 → 点菜下单支付，全程不到 1 分钟
- **共享单车**：扫码→开锁元服务→注册（首次）→开锁→关锁→自动扣款，无 App 残留
- **天气卡片**：桌面天气卡片每 30 分钟自动刷新，划一下就能看到未来几小时
- **快递查询**：搜索框输入快递单号 → 快递元服务直接显示物流轨迹
- **健康码/行程卡**：疫情期间典型的元服务场景，用完即走无需安装

## 常见误解（FAQ）

- **❌ 误区：「元服务就是 PWA 的鸿蒙版」** 不完全一样。PWA 本质是 Web 技术栈，受限于浏览器能力。元服务是原生应用，能用全部系统 API（蓝牙、NFC、传感器），性能远超 Web，体积也更大（PWA 通常 < 2MB，元服务 ≤ 10MB）。

- **❌ 误区：「元服务可以替代 App」** 互补而非替代。元服务处理"单一高频场景"（点餐、查询），传统 App 处理"复杂多场景"（社交、编辑、创作）。一个品牌可以同时有 App 和元服务，覆盖不同触达场景。

- **❌ 误区：「元服务不需要审核，随便上架」** 元服务和 App 一样需要上架华为应用市场并过审。且由于"免安装"的特性，安全审核更严格——涉及支付、个人信息采集的元服务需要额外的安全评估。

- **❌ 误区：「元服务不能赚钱」** 元服务支持华为支付、广告、会员订阅，盈利模式和 App 一致。且因免安装转化率高，在某些场景下（如餐饮、票务）ROI 反而更高。

## 一句话总结

元服务的本质是：把一个 App 最核心的"那一下"拆出来，让用户以最低成本完成——这是移动互联网从"应用分发"走向"服务分发"的趋势。
