## 一句话概括

框架没有普适最优解——社交 Feed 流、电商秒杀、金融交易、企业工具、IoT 面板……每种场景对"流畅度/动态化/原生化/合规性"的权重完全不同，选型本质是按场景打分的加权决策。

## 核心知识点

### 1. 社交 Feed 流：列表性能为王

核心需求：无限滚动 60fps、图片快速加载、视频自动播放

**推荐：Flutter（主 Feed）**
- ListView.builder 无需创建原生 View，5000+ 条数据满帧滚动
- 视频/图片渲染在 Engine 内完成，无跨语言通信

RN 也可以（如果已有 React 技术栈 + 列表项简单），但超过 2000 条复杂卡片需要大幅优化才能稳定 60fps。

### 2. 电商 App：动态化 + 列表并重

核心需求：秒杀流畅、运营页面动态配置、第三方 SDK（支付/地图/推送）

**推荐：RN（主链路）+ H5（运营页）**
- CodePush 实现运营页热更新，不需要发版
- 第三方 SDK 集成成熟（支付宝/微信支付/高德地图都有现成的 RN 包）
- 列表性能中等——对于电商首页瀑布流够用

Flutter 也可以胜任，但缺少 CodePush 会导致运营活动依赖发版节奏。

### 3. 金融/银行：合规 > 一切

核心需求：安全合规、系统级能力（指纹/面容/证书）、政企准入

**推荐：鸿蒙 ArkUI（国内）或原生（国外）**
- 国内政企/金融项目适配鸿蒙是国家要求，不是技术选择
- 生物识别、安全沙箱、加密引擎都是系统级能力，跨端框架难做到原生级别的安全

Flutter/RN 只适合金融 App 的非核心页面（理财产品展示、资讯）。

### 4. 企业 OA/管理后台：Web 复用优先

核心需求：快速迭代、与 Web 版本共享组件、性能要求低

**推荐：React Native**
- 已有的 React Web 组件可以直接搬，不需要重写
- 管理后台的列表/表单/审批流对性能要求不高
- 团队 Web 背景，上手零成本

### 5. IoT/车机/智能设备：系统集成深度

核心需求：蓝牙/WiFi 直连、传感器数据流、低功耗

**推荐：鸿蒙 ArkUI（鸿蒙 IoT 生态）或原生**
- 鸿蒙"1+8+N"生态下，选 ArkUI 可获得系统级分布式能力（设备发现、数据流转）
- Flutter 在这些场景下需要大量的 Platform Channel 调用原生 API，开发成本高

## 其实你每天都在用

- **微信朋友圈**的 Feed 流——假设用 Flutter 做，长列表性能是最不需要担心的部分
- **淘宝的"有好货"推荐瀑布流**——用 RN 做，CodePush 更新推荐算法相关的 UI 无需发版
- **建设银行 App 的鸿蒙版**——没什么"技术理由"，是"鸿蒙原生应用"的合规要求
- **字节飞书的移动端**——用 RN 是因为飞书 Web 版就是 React，组件直接复用
- **华为手表 App**——用 ArkUI 是因为华为 Watch 只支持鸿蒙，没有第二选择

## 常见误解（FAQ）

**❌ 误区：社交 App 一定选 Flutter 因为它列表性能最好。**

✅ 即时通讯 App 对列表性能要求极高，但微信/QQ 也没有用 Flutter——因为它们需要的不仅是列表滚动性能，还有音视频通话、推送、后台保活等系统级能力。Flutter 擅长的是"纯 UI 性能"，不是"所有性能"。

**❌ 误区：企业应用性能要求低，用什么都一样。**

✅ 企业应用的性能瓶颈往往和消费 App 不同——不是列表滚动，而是**大量表单校验、复杂业务逻辑、离线数据同步**。RN 的 JS 引擎在这些场景下可能成为瓶颈（大量计算在主线程），而 Flutter 的 Dart AOT 编译对 CPU 密集逻辑更友好。

**❌ 误区：IoT 场景优先考虑跨端框架，一套代码多设备。**

✅ IoT 设备的能力极度碎片化（不同厂商的蓝牙协议、不同的传感器 API），跨端框架的"统一抽象"在这里适得其反——你需要的是设备特化代码，不是统一代码。IoT 的正确方案是：原生业务层 + 跨端 UI 层分离。

**❌ 误区：安全性要求高的场景（金融/支付）不能用跨端框架。**

✅ 跨端框架本身不会降低安全性，关键看**数据加密在哪一层做、密钥存在哪**。金融 App 用 RN/Flutter 做 UI 展示完全没问题，但加解密、证书验证、生物识别必须在原生层通过系统 API 完成——"UI 用跨端，安全走原生"是正确架构。

## 一句话总结

框架选型不是比性能数字和 Star 数，而是回答"你的业务最不能妥协的是什么"——列表性能（Flutter）、热更新（RN）、系统原生（ArkUI）、Web 复用（RN）——答案只有一个，但问题需要用心想。
