## 一句话概括

面试官问"怎么做暗黑模式"，很多人上来就答"用 CSS 变量 + 加个 `.dark` 类 + 存 localStorage"。这三句都没错，但**全在同一个层次上**——面试官想听的是这几个问题的答案：

1. **状态落在哪**：为什么落点是 `html` 上的属性/类，而不是一串媒体查询？
2. **优先级谁压谁**：系统偏好和用户手动选择同时存在时，谁赢？怎么用 CSS 表达这件事？
3. **首屏怎么不闪**：为什么"闪一下"是个**时序问题**而不是样式问题？修它需要哪三个硬条件？
4. **原生控件和图片算不算在内**：为什么只改自己的颜色，深色模式看起来永远"没做完"？

想清楚这四个问题，暗黑模式就从一个"加个开关"的小需求，变成了一个**主题系统的工程化落点**问题。

## 核心知识点

### 1. 落点：为什么必须是属性，而不是媒体查询

先说结论。主题状态有三个层级，优先级从高到低：

> **用户显式选择 > 系统偏好 > 产品默认**

CSS 表达这三层，靠的是 `@media`（能表达"跟随系统"）配合一个**属性选择器**（能表达"用户否决")：

```css
:root {                                  /* ① 产品默认 */
  --bg: #ffffff;
  --fg: #0d0f13;
}

@media (prefers-color-scheme: dark) {    /* ② 跟随系统 */
  /* 关键：用户明确选了浅色时，这一整块失效 */
  :root:not([data-theme='light']) {
    --bg: #0a0b0d;
    --fg: #eef1f5;
  }
}

:root[data-theme='light'] { --bg: #ffffff;  --fg: #0d0f13; }  /* ③ 用户显式覆盖 */
:root[data-theme='dark']  { --bg: #0a0b0d;  --fg: #eef1f5; }
```

那个 `:not([data-theme='light'])` 不是可有可无的装饰，**它是"用户否决系统"的唯一实现手段**。实测（Chrome，强制深色系统）：

```text
深色系统 + 无 data-theme：
  --probe（带 guard）  = media-dark-without-light-attr   ← 媒体查询生效
  --probe2（无 guard） = media-plain-matches             ← 一样生效（都正常）

深色系统 + data-theme="light"：
  --probe（带 guard）  = light-default                   ← 被挡住了 ✅
  --probe2（无 guard） = media-plain-matches             ← 用户的手动选择被无视 ❌
```

**没有 guard 的写法，用户点了"浅色"也压不过系统深色** —— 因为媒体查询只看操作系统，不看你的 DOM 属性。这就是"媒体查询不能单独作为落点"的实证。

顺便把状态模型定清楚。常见的开关是**三态**（浅色 / 跟随系统 / 深色），但存储里不需要存 `'auto'`：

```js
const root = document.documentElement;

function setTheme(choice) {          // 'light' | 'dark' | 'auto'
  if (choice === 'auto') {
    localStorage.removeItem('theme'); // 不存值，本身就是 auto 状态
    delete root.dataset.theme;        // 交还给 CSS 媒体查询
  } else {
    localStorage.setItem('theme', choice);
    root.dataset.theme = choice;      // 落点：html 上的属性
  }
}
```

**"auto" 是"没有覆盖"，不是"第三种主题"** —— 这个心智模型一立，CSS 那三条规则的写法就顺理成章了。

### 2. 首屏不闪：这是一个时序问题，不是样式问题

先复现一下"闪"是怎么来的。浏览器解析 HTML 是从上往下的：

```text
HTML 到达 → 应用 CSS（此时还是默认的浅色）→ 画第一帧（白的）
          → React 水合、跑 useEffect → 读 localStorage → setState → 再画一帧（黑的）
```

中间那帧白的就是闪。**它不是样式写错了，是"读偏好"这件事发生得太晚**。所以修法的方向只有一个：**在第一帧之前把属性写好**。

浏览器里唯一能保证"在任何绘制之前跑完"的脚本形态是——**`<head>` 里的一段同步内联脚本**：

```html
<head>
  <meta charset="utf-8">
  <meta name="color-scheme" content="light dark">
  <!-- 必须是同步内联脚本，且尽量靠前 -->
  <script>
    (function () {
      try {
        var t = localStorage.getItem('theme');        // 'light' | 'dark' | null
        if (t === 'light' || t === 'dark') document.documentElement.dataset.theme = t;
      } catch (e) { /* 隐私模式下可能抛异常，忽略 */ }
    })();
    // 加载阶段先关过渡，避免首屏"渐变色"动画
    document.documentElement.classList.add('no-transition');
  </script>
  <link rel="stylesheet" href="/style.css">
</head>
```

三条硬要求，缺一条就白写：

| 要求 | 为什么 |
| --- | --- |
| 必须内联 | 外链脚本要走一次网络请求，时序无法保证 |
| 不能是 deferred 脚本 | 带 `defer` 的脚本要"等文档解析完再执行"，首帧早就画了 |
| 不能带 `async`、不能是模块脚本 | `async` 何时执行不确定；`type="module"` 天然是 deferred 语义 |

注意脚本里**只在用户显式选过时才写属性**——没选过就什么都不做，让 CSS 的媒体查询接管。这样"自动"状态完全零 JS 参与，也就少一条出错路径。

框架里的对应动作：Next.js 用 `beforeInteractive` 策略；再往前走一步是 **SSR 直接从 cookie 读主题、写进 HTML 首字节**——那样连内联脚本都不需要，因为首屏 HTML 本身就是对的。React 侧还要注意一个坑：**初始 state 必须和这段脚本读同一个来源**，否则服务端渲染的浅色 HTML 和客户端算出的深色状态对不上，会报水合不一致。

### 3. `color-scheme`：最容易漏、性价比最高的一行声明

很多人做完深色模式会疑惑："为什么我的滚动条、`<select>`、`<input type="date">` 还是白的？"——因为**这些是浏览器的原生 UI，你的 CSS 管不到，得靠 `color-scheme`**。

MDN 对它作用的描述很具体：它会让 UA 改变**画布底色、滚动条、表单控件的默认颜色，以及拼写检查下划线这类浏览器提供的 UI**。实测结论（Chrome 151）：

```text
#darkIsland（声明了 color-scheme: dark）里的 input 背景 = rgb(59, 59, 59)
没有声明 color-scheme 的页面里的 input 背景       = rgb(255, 255, 255)
  ↑ 注意：这一行在"强制深色系统"下仍然是白色
```

**没声明 `color-scheme` 的页面，原生控件在深色系统下也不跟随** —— 这就是"看起来没做完"的真正根因。`color-scheme` 还是**可继承**的（上面那个 `input` 的 computed 值就是 `dark`），所以可以只在一个子树里声明，做"局部深色岛"。

正确配法：跟随系统和手动覆盖各写一次，并且要**同时改 `color-scheme`**：

```css
:root { color-scheme: light dark; }          /* 零 JS 跟随系统（推荐默认） */
:root[data-theme='light'] { color-scheme: light; }
:root[data-theme='dark']  { color-scheme: dark; }
```

再加一个 HTML 侧的配合（MDN 明确写它"有助于避免页面加载时不必要的屏幕闪烁"）：

```html
<!-- 放在任何 CSS 之前 -->
<meta name="color-scheme" content="light dark">
```

最后一个关键字值得记：`color-scheme: only light` —— 它**禁止 UA 覆盖**，官方用途就是关掉 Chrome 的 Auto Dark Theme（把已经适配好的页面又被强制反色一遍）。兼容性很宽：`color-scheme` Chrome 81 / Firefox 96 / Safari 13。

### 4. `light-dark()`：写法最省，但有一个必须记住的前提

`color-scheme` 的声明一旦立好，就能用 `light-dark()` 把两个值写在一行里：

```css
/* 前提：:root 上必须有 color-scheme: light dark（或 meta） */
:root { color-scheme: light dark; }

body { background: light-dark(#ffffff, #0a0b0d); color: light-dark(#0d0f13, #eef1f5); }
```

**这个前提不是建议，是硬性的。** 实测对比：

```text
页面有 <meta name="color-scheme">：
  强制深色系统 → light-dark(rgb(1,1,1), rgb(2,2,2)) = rgb(2, 2, 2)   ✅ 取深色

页面没有 meta、元素也没声明 color-scheme：
  强制深色系统 → light-dark(rgb(1,1,1), rgb(2,2,2)) = rgb(1, 1, 1)   ❌ 仍是浅色值
```

**没声明 `color-scheme` 时，`light-dark()` 会一直返回浅色那个值，跟系统偏好无关。** 面试里能主动说出这条，比背语法有用得多。

兼容性上它比 `color-scheme` 晚很多：Chrome 123 / Firefox 120 / Safari 17.5（≈2024 年）。要保旧浏览器的写法还是老老实实写变量覆盖。

### 5. 切换本身：改属性不重排，但过渡别加在首屏

面试官追问"切换主题会不会触发重排"时，答案取决于你切的是什么：

- **✅ 切 `data-theme` 属性** → 只改自定义属性的值 → 触发 **style recalc + paint**，**不触发 layout**（改的是颜色，不动几何）
- **❌ 在 JS 里逐个元素改内联样式** → 元素多的时候，每次写 `style` 都可能引起额外的样式计算与布局

所以正确姿势是"**一处开关，全局响应**"：切一个属性，所有读 `var(--x)` 的地方自己变。

再看过渡。两个坑：

```css
/* ❌ 会把 width / height / margin 也一起过渡 */
html { transition: all .3s; }

/* ✅ 只列颜色相关属性 */
html { transition: background-color .25s, color .25s, border-color .25s; }
```

`transition: all` 的坏处不是"切主题变慢"，而是**任何一次布局属性变化都会意外变成动画**，这类 bug 很难查。

第二个坑是**过渡会在加载阶段也跑一遍**。如果主题是在 JS 里后置应用的（比如水合之后），页面就会从浅色一路"渐变"到深色，比直接闪一下更奇怪。做法是加载阶段先关掉过渡，第一帧之后再打开：

```js
// head 里的内联脚本负责加类，之后移除（顺序不能反）
document.documentElement.classList.add('no-transition');
requestAnimationFrame(() => document.documentElement.classList.remove('no-transition'));
```

```css
html.no-transition, html.no-transition * { transition: none !important; }

/* 尊重系统设置：用户要求减少动效时，主题切换就别做动画了 */
@media (prefers-reduced-motion: reduce) {
  html, html * { transition: none !important; }
}
```

### 6. 跨标签页同步：`storage` 事件的两条边界（实测）

主题写进 `localStorage` 之后，另一个标签页怎么知道？答案就是 **`storage` 事件**，不用上 `BroadcastChannel`。但它有两条边界必须知道，实测（同源两个 window）：

```text
父窗口自己 localStorage.setItem('theme','dark')
  → 父窗口收不到 storage 事件                      ← 边界一：自己写，自己收不到

iframe（同源、不同 window）写入
  → 父窗口收到：e.key='theme'、e.newValue='light-from-frame'   ← 边界二：只在"别的 window"触发
```

所以监听逻辑要写对：

```js
// 只处理"别的标签页"的改动；本标签页的 UI 变化由 setTheme 自己负责
addEventListener('storage', (e) => {
  if (e.key !== 'theme') return;
  if (e.newValue) document.documentElement.dataset.theme = e.newValue;
  else delete document.documentElement.dataset.theme;   // 被清空 = auto
});
```

**边界一的实践含义：把"更新 DOM"这一步封在 `setTheme` 里，别指望监听器帮你更新当前页面。** 这也是为什么有些库会在同文档内**手动派发一个 `StorageEvent`**——就是把"跨标签页走事件"和"本页走事件"统一成一条路径（VueUse 的 `useStorage` 就是这么做的）。另外，`data-theme` 变化时别忘了同步 `<meta name="theme-color">`：

```js
function syncThemeColor(theme) {
  let meta = document.querySelector('meta[name="theme-color"]:not([media])');
  if (!meta) {
    meta = document.createElement('meta');
    meta.name = 'theme-color';
    document.head.appendChild(meta);
  }
  meta.content = theme === 'dark' ? '#0a0b0d' : '#ffffff';
}
```

因为**`<meta name="theme-color" media="(prefers-color-scheme: dark)">` 只认系统偏好，不认你手写的 `data-theme`**——静态声明解决"跟随系统"，手动切换那一路必须 JS 补。

### 7. 深色不是反色：图片与配色的三条官方口径

**图片**：`filter: invert(1)` 是深色模式里最常见的"偷懒错"，它会把照片的色相整个翻掉、肤色变得很怪。要么轻调亮度，要么按偏好换源：

```css
/* ❌ 照片色彩全毁 */
[data-theme='dark'] img { filter: invert(1); }

/* ✅ 只压掉过亮的光，色相保持不变 */
[data-theme='dark'] img { filter: brightness(.85) contrast(1.05); }
```

```html
<!-- 需要真正两张图（比如明暗两套插画）时用 picture -->
<picture>
  <source srcset="/hero-dark.png" media="(prefers-color-scheme: dark)">
  <img src="/hero-light.png" alt="">
</picture>
```

图标和 Logo 更好办：SVG 用 `fill="currentColor"`，颜色跟着 `color` 走，天然随主题。

**配色**，Material Design 的三条口径是面试可以直接引用的：

| 口径 | 具体做法 | 原因 |
| --- | --- | --- |
| 用深灰而不是纯黑 | 表面色推荐 **`#121212`** | 纯黑上没有阴影的表达空间，难以表达层级；对比度太高反而更累眼 |
| 正文用 off-white | 如 `#E0E0E0`，或白色 87% 不透明度 | 纯白配纯黑的对比可到 **15:1 以上**，会出现 halation（文字"发晕/在抖"），对散光用户尤其不友好 |
| 主色要降饱和 | 降饱和直到过 WCAG AA 的 **4.5:1** | 浅色下舒服的饱和色放到深底上会"发荧光"，看着刺眼 |

**层级用"更亮"表达，而不是用阴影**：Material 的做法是上层元素叠一层半透明白色蒙版，0dp 时 0%，最高 24dp 约 16%。这条在面试里说出来，说明你不只是"会写代码"，还知道深色是**另一套设计系统**而不是反色。

## 其实你每天都在用

- 手机上装的应用里，能在"设置 → 外观"里选"浅色 / 跟随系统 / 深色"的，基本就是上面这套三态模型。
- 打开 GitHub、Stack Overflow，右上角切换主题后**整个页面不刷新**、颜色瞬间变——因为切的是一个 `data-theme` 属性的值。
- 你第一次打开某个网站时它"先白后黑"闪一下，就是没做好第 2 节那段内联脚本；如果它从头到尾都是对的深色，多半是 SSR 读了 cookie。
- 某站点在深色模式下滚动条还是白色的，就是漏了 `color-scheme`。
- 深色模式下某个按钮变荧光红、看久了刺眼，就是主色没有降饱和。
- 你电脑上几款应用（编辑器、文档工具）的深色模式是"更亮的灰"分层，而不是纯黑——这是 Material 那套 elevation 覆盖。
- 网页里的插画在深色模式下"换了一张"（而不是变色），就是 `<picture>` + `media` 换源。
- 你开了某个深色主题的网站，然后在系统里切换明暗，页面**立刻跟着变**——这就是媒体查询在 `auto` 状态下零 JS 生效。

## 常见误解（FAQ）

**❌ 误区一："颜色换成 CSS 变量就做完了"**

只做了第一层。还差两件：**`color-scheme`**（不然原生控件、滚动条在深色系统下不跟随）和**首屏时序**（不然刷新就闪）。这两条恰恰是页面"看起来没做完""感觉不太对"最常见的原因。

**❌ 误区二："写媒体查询就够了，不用加属性"**

不够。实测已证明：**深色系统下用户手动选浅色，没有 guard 的媒体查询会把用户的选择直接无视**。媒体查询只能表达"跟随系统"，表达不了"用户否决系统"。落点必须是 `html` 上的属性或类。

**❌ 误区三："防闪脚本放到 `DOMContentLoaded` 或 `defer` 里就行"**

不行。这三者（`defer`、`DOMContentLoaded`、`type="module"`）的共同点是**都要等文档解析完**，而首帧早在这之前就画出来了。防闪需要的是"解析到这一行立刻同步执行"，所以只能内联、只能不加 `defer`/`async`。

**❌ 误区四："深色模式就是把明暗反一下"**

反色只保证"看得见"，不保证"看得舒服"。三个具体代价：纯黑底 + 纯白字会出现 halation（对比度超过 15:1 后反而更累眼）；纯黑没有表达层级的空间（得用深灰 `#121212` + 更亮的表面）；浅色模式下的饱和主色放到深底上会发荧光（要降饱和到过 4.5:1）。

**❌ 误区五："切主题很贵，会触发整页重排"**

看你怎么切。**改 `html` 上的属性 → 只走 style recalc + paint，不触发 layout**，因为动的全是颜色。真正会贵的是两种写法：在 JS 里逐元素改内联样式；以及滥用 `transition: all`，让所有布局属性都变成动画。

**❌ 误区六："跨标签页同步主题要用 `BroadcastChannel`"**

`storage` 事件就够，而且它本身就是"同源其他窗口的存储变化通知"。但必须知道它的边界：**写入的那个窗口自己收不到事件**。所以本标签页的 UI 必须在 `setTheme` 里同步更新，监听器只负责处理"别人改的"。要统一成一条路径，可以在本页手动派发一个 `StorageEvent`。

**❌ 误区七："浏览器支持 `light-dark()` 就能用"**

还差一个前提：**`:root` 上必须声明 `color-scheme: light dark`（或用 `<meta name="color-scheme">`）**。实测在没有声明时，即使系统是深色，`light-dark()` 也返回浅色的那个值。所以它不是"新语法糖"，而是**依赖 `color-scheme` 的语法糖**。

## 一句话总结

**主题切换的落点永远是一个属性（用户选择压系统、系统压默认），防闪的关键是把它写在首屏第一帧之前的同步内联脚本里，而"看起来没做完"几乎总是因为漏了 `color-scheme`、`theme-color` 和图片这三处 CSS 管不到的地方。**
