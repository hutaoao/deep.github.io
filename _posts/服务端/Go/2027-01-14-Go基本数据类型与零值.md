## 一句话概括

从前端过来第一个不习惯的地方：JS 里 `let a` 之后 `a` 是 `undefined`，还能一路传下去变成 `NaN`；Go 里 `var a int` 之后 `a` 就是 `0`，连"有没有值"这个疑问都不存在。

面试问这块，核心三句话就够：

- **每个类型都有零值**，声明即初始化，所以没有 `undefined` / `null` 这种"有这个变量但没值"的中间态；
- **类型是精确的**：`int32 + int64` 直接编译不过，没有 JS 那种自动提升；
- **转换必须写在明面上**：`string(65)` 得到的是 `"A"` 不是 `"65"`，这是最高频的坑。

## 核心知识点

### 1. 类型清单：位宽定死，只有 int 看平台

```go
package main

import (
	"fmt"
	"unsafe"
)

func main() {
	fmt.Println(unsafe.Sizeof(int(0))*8, unsafe.Sizeof(int32(0))*8)   // 64 32
	fmt.Println(unsafe.Sizeof(float64(0))*8, unsafe.Sizeof(true))     // 64 1
	fmt.Println(unsafe.Sizeof(""))                                    // 16
}
```

`unsafe.Sizeof` 只是拿来量一下，别在业务代码里用。量出来的结论整理成表：

| 类型 | 位宽 | 要记住的点 |
| --- | --- | --- |
| `int8/16/32/64`、`uint…` | 8/16/32/64 | 位宽固定，跨平台一致 |
| `int` / `uint` | **32 或 64** | 跟平台走，本机 64 位就是 8 字节 |
| `float32` / `float64` | 32/64 | 不带小数点的字面量默认 `float64` |
| `byte` | 8 | 就是 `uint8` 的**别名**，不是新类型 |
| `rune` | 32 | 就是 `int32` 的**别名**，存一个 Unicode 码点 |
| `bool` | 1 | 只有 `true`/`false`，**不能拿 0/1 当布尔** |
| `string` | 头 16 字节 | 不可变字节序列（指针 + 长度） |

`byte` / `rune` 是别名这件事值得亲手打一次 `%T`：

```go
package main

import "fmt"

func main() {
	var b byte = 'A'
	var r rune = 'A'
	fmt.Printf("%v %T | %v %T\n", b, b, r, r) // 65 uint8 | 65 int32
}
```

打印出来是 `uint8` 和 `int32`，不是 `byte` 和 `rune`——所以 `byte` 和 `uint8` 之间不需要转换，它们本来就是一个类型。

**`int` 随平台变**这一点在工程里是真会咬人的：本地 64 位机上 `int` 装得下 100 亿，部署到 32 位环境直接溢出。所以凡是**要落库、要跨网络传、要跨平台跑**的数字，一律写死 `int64` / `uint32`，别用裸 `int`。

### 2. 零值：Go 不是"没有值"，而是"值是零"

```go
package main

import "fmt"

type User struct {
	Name string
	Age  int
	Tags []string
}

func main() {
	var n int
	var s string
	var u User
	fmt.Printf("%d %q %+v\n", n, s, u) // 0 "" {Name: Age:0 Tags:[]}
	fmt.Println(u.Tags == nil)         // true
}
```

注意两个细节：字符串零值是空串但不是 `nil`（`string` 不是引用类型），而切片零值**是 `nil`**，`== nil` 成立。

面试问"Go 为什么没有 undefined"，答这三层：

1. **编译器保证**：变量分配的那一刻内存就是清零的，零值是按类型确定的规则算出来的，不需要运行时额外标记。所以语言层面根本不存在"分配了但没值"的状态。
2. **零值可预测，不会传染**：`int` 是 0、`string` 是 `""`、`bool` 是 `false`、指针/切片/map/接口是 `nil`。不会出现 JS 那种 `undefined + 1 = NaN`、`NaN !== NaN` 的连锁灾难。
3. **代价是"忘记赋值"不会报错**：JS 拿到 `undefined` 至少能在控制台一眼看出来，Go 拿到 0 你根本不知道那是默认值还是业务值。所以工程上要么显式初始化，要么用 `*int` / `sql.NullInt64` 这类类型区分"没值"和"零"。

零值这条链上最经典的追问是"nil 切片和 nil map 是不是一样不能动"，答案正好相反——这里不展开了，前面《变量、常量与 iota》已经踩过一遍。

### 3. 类型转换：一个都不能省，而且 `string(int)` 是陷阱

Go 没有隐式转换，连 `int32` 加 `int64` 都不行：

```go
package main

import "fmt"

func main() {
	var x int32 = 1
	var y int64 = 2
	// fmt.Println(x + y) // ❌ invalid operation: x + y (mismatched types int32 and int64)
	fmt.Println(int64(x) + y) // ✅ 3
}
```

报错原文就长这样：`invalid operation: x + y (mismatched types int32 and int64)`。这不是语言在"刁难"，而是**让每一次精度可能丢失的地方都出现在 diff 里**——隐式转换的 bug 最难查，因为它不报错。

真正的高频坑是这几个：

```go
package main

import "fmt"

func main() {
	pos, neg := 3.9, -3.9
	fmt.Println(int(pos), int(neg)) // 3 -3   ← 向零截断，不是四舍五入

	// fmt.Println(int(3.9)) // ❌ cannot convert 3.9 (untyped float constant) to type int

	fmt.Printf("%q %q %q\n", string(65), string(0x4f60), string(-1)) // "A" "你" "�"  ← go vet 会报这一行
}
```

三个点全是面试爱问的：

- **float → int 是截断不是取整**：`int(3.9)` 是 3、`int(-3.9)` 是 -3，想四舍五入得用 `math.Round`。
- **常量转换更严格**：`int(3.9)` 写在常量位置上直接编译报错 `cannot convert 3.9 (untyped float constant) to type int`——因为常量转换要求"值能被目标类型精确表示"，3.9 不是整数就是不合法。变量没这个限制。
- **`string(整数)` 转的是码点不是数字**：`string(65)` 是 `"A"`，`string(0x4f60)` 是 `"你"`，`string(-1)` 是替换字符 `�`（U+FFFD）。想要数字的字符串用 `strconv.Itoa(65)`。

`go vet` 专门为这条加了检查，跑一下就会骂你：

```
main.go:7:7: conversion from int64 to string yields a string of one rune, not a string of digits
```

所以"数字转字符串用什么"这种题，标准答案是 `strconv.Itoa` / `strconv.FormatInt`，`fmt.Sprintf("%d", n)` 也行，唯独不是 `string(n)`。

### 4. 溢出与精度：变量静默回绕，常量直接编译不过

```go
package main

import "fmt"

func main() {
	var a int8 = 127
	a++
	var b uint8 = 255
	b++
	fmt.Println(a, b) // -128 0

	// const small int8 = 200 // ❌ cannot use 200 (untyped int constant) as int8 value in constant declaration (overflows)
}
```

这里的差别是面试的加分点：

- **变量溢出不会 panic，按补码规则回绕**。Go 规范明确写了：有符号整数的 `+ - * / <<` 可以合法溢出，结果由表示方式确定，**不会触发运行时 panic**；无符号整数按 2ⁿ 取模。规范还禁止编译器假设"溢出不会发生"（所以不会出现 C 里那种 `x+1 > x` 被优化成恒真的鬼故事）。
- **常量溢出是编译期错误**，因为常量的运算精度是无限的，装不下就直接骂。

回绕这个特性离"死循环"只有一步。`for b := byte(250); b <= 255; b++` 看着只跑 6 轮，实测是永远跑不完的——255 加 1 变回 0，条件一直成立：

```go
func main() {
	var b byte
	for b = 250; b <= 255; b++ {
		fmt.Println(b) // 250 251 252 253 254 255 0 1 2 3 …
	}
}
```

拿 `count` 打点强行打断，看到的是"跑到第 11 轮时 b 已经是 4"。所以循环边界永远写严格小于 `<`，让编译器帮你拦住 —— 写成 `b < 256` 的话直接编译报错 `256 (untyped int constant) overflows byte`。

再看整数除法和浮点：

```go
package main

import "fmt"

func main() {
	fmt.Println(7/2, -7/2, 7%2, -7%2) // 3 -3 1 -1

	x, y := 0.1, 0.2
	fmt.Println(x+y, x+y == 0.3) // 0.30000000000000004 false
	fmt.Println(0.1+0.2 == 0.3)  // true ← 注意！
}
```

- **整数除法向零截断**，两个 `int` 相除永远是 `int`，想要小数得先转 `float64`。这也是"金额为什么不能用 float、要用分（整数）存"的起点。
- **浮点数不能直接 `==`**，变量版 `0.1+0.2` 是 `0.30000000000000004`。但**常量版比较结果是 `true`**——因为未类型化常量在编译期用任意精度精确计算，`0.1+0.2` 真的等于 `0.3`。这个反差特别容易被面试官拿来确认你到底是背的还是真跑过。

## 落到项目里长什么样

1. **主键和金额一律 `int64`**：数据库 `BIGINT` 对应 `int64`，别用 `int`；金额用"分"存 `int64`，只在展示层除 100。
2. **接口返回错误码用 `iota` 常量 + 自定义类型**：`type Code int`，比裸 `int` 多一层编译期检查。
3. **配置结构体直接 `var cfg Config`**：拿到就是"全零但可用"的对象，超时时间自己想给默认值就显式给，别指望零值合理（`Timeout=0` 在 Go 里通常意味着"永不超时"，这是个真坑）。
4. **区分"没传"和"传了零值"**：前端 JSON 里 `age: 0` 和没传 `age` 反序列化到 `int` 字段后长得一模一样，要区分就得用 `*int` 或 `sql.NullInt64`——这是前端最容易忽略的语义差异。
5. **数字转字符串统一走 `strconv`**：项目里搜一遍 `string(` 后面跟变量的地方，几乎每处都是 bug 或可读性问题。

## 常见误解（FAQ）

**❌ 误区1："Go 没有 null / undefined，所以不会有空值问题"**

只有引用类类型的零值是 `nil`：指针、切片、map、channel、接口、函数。`int` 是 0、`string` 是 `""`。所以空值问题一个都没少，只是从"判 undefined"变成了"判 nil"和"判零值"，后者更隐蔽。

**❌ 误区2："`byte` 是一个独立的字符类型"**

`byte` 就是 `uint8` 的别名，`rune` 就是 `int32` 的别名。`%T` 打出来是 `uint8` / `int32`。它们和底层类型之间零成本互换，不需要转换。

**❌ 误区3："`string(65)` 得到 `"65"`"**

得到的是 `"A"`，因为 `string(int)` 的语义是"把这个整数当成 Unicode 码点"。要数字用 `strconv.Itoa`。`go vet` 会报 `conversion from ... to string yields a string of one rune`。

**❌ 误区4："Go 溢出会 panic"**

变量溢出不会 panic：`int8(127)+1` 得到 `-128`，`uint8(255)+1` 得到 `0`，规范说结果是确定性回绕。会报错的是**常量**溢出（编译期）。所以运行时判断溢出得自己算，或者用 `math.MaxInt64 - a < b` 这种写法。

**❌ 误区5："`int(3.9)` 会四舍五入成 4"**

向零截断，得 3。而且如果 3.9 是**常量**（字面量直接写），连编译都过不去：`cannot convert 3.9 (untyped float constant) to type int`。

**❌ 误区6："`int` 在哪儿都是 8 字节"**

`int` 的位宽跟平台走，32 位平台是 4 字节。要稳定就写 `int64`。另外一个连带影响：32 位平台上 `atomic.AddInt64` 要求被操作的变量 64 位对齐，否则运行时 panic——用 `atomic.Int64` 类型则自动对齐，这也是官方推荐写法。

## 一句话总结

Go 用"声明即零值"消灭了 undefined，用"禁止隐式转换"消灭了静默精度丢失，代价是溢出依旧静默回绕——面试就答这三句，再补一句 `string(65)` 是 `"A"` 不是 `"65"`。
