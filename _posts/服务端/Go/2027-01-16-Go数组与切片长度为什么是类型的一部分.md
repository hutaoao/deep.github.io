## 一句话概括

JS 里 `[1, 2, 3]` 长度随便变，Go 里长度一旦写死就是**类型的一部分**：`[3]int` 和 `[4]int` 是两个互不兼容的类型，跟 `int` 和 `string` 一样不能互转。

这条设计引出一串连锁反应，面试基本就按这个顺序问：

- 数组为什么不能动态加元素？
- 数组传参是值传递还是引用传递？
- 数组能比较吗？切片为什么不能？
- 既然有切片，数组还有存在的必要吗？

下面按顺序答。

## 核心知识点

### 1. 长度写进类型，所以数组是"一整块值"

```go
package main

import "fmt"

func change(a [3]int)     { a[0] = 999 } // 收的是副本
func changePtr(a *[3]int) { a[0] = 999 } // 收的是地址

func main() {
	a := [3]int{1, 2, 3}
	b := a
	b[0] = 9
	fmt.Println("赋值后：", a, b) // [1 2 3] [9 2 3]

	change(a)
	fmt.Println("传值后：", a) // [1 2 3]  没变
	changePtr(&a)
	fmt.Println("传指针后：", a) // [999 2 3] 变了
}
```

结论一句话：**Go 的数组是值类型，赋值和传参都是把整块内存复制一份**，想改原数组只能传指针 `*[3]int`。

为什么能做到"整块复制"？因为长度是类型的一部分，编译器在编译期就知道这个类型占多少字节（`[3]int` 就是 24 字节），可以直接把它当值塞进栈、结构体、甚至另一个数组里。

代价是长度必须完全一致，`[3]int` 和 `[4]int` 直接编译不过：

- 写 `var x [4]int = a` 报 `cannot use a (variable of type [3]int) as [4]int value in variable declaration`
- 想让编译器自己数长度用省略号：`[...]int{1, 2, 3}` 就是 `[3]int`
- `len(arr)` 是**编译期常量**，能直接拿去声明另一个数组：`var c [len(a)]int`（实测合法）

### 2. 因为是值、长度又是类型，数组能干两件切片干不了的事

**第一件：直接用 `==` 比较。** 只要元素类型可比较，数组就能一次比完：

```go
package main

import "fmt"

func main() {
	fmt.Println([3]int{1, 2, 3} == [3]int{1, 2, 3}) // true

	// 切片不行，编译器直接拦：
	// s1, s2 := []int{1}, []int{1}
	// fmt.Println(s1 == s2) // ❌ invalid operation: s1 == s2 (slice can only be compared to nil)
}
```

**第二件：当 map 的 key。** `[2]int` 表示坐标、`[2]string` 表示 (type, id) 组合，天然适合查重：

```go
package main

import "fmt"

func main() {
	k := [2]int{1, 2}
	m := map[[2]int]string{k: "x=1,y=2"}
	fmt.Println(m[[2]int{1, 2}]) // x=1,y=2

	// m2 := map[[]int]string{} // ❌ invalid map key type []int
}
```

把这两件事和"长度是类型"串起来：能比较、能当 key 的前提都是**编译器知道它的确切布局**，而 `[]int` 的长度是运行时才知道的，所以做不到。

一张表把区别钉死（面试可以直接背）：

| | 数组 `[N]T` | 切片 `[]T` |
| --- | --- | --- |
| 长度 | 类型的一部分，编译期定死 | 运行时字段，能变 |
| 赋值 / 传参 | 复制**整块数据** | 只复制描述符（3 个字长） |
| `==` 比较 | 元素可比较就能比 | 只能和 `nil` 比 |
| 当 map key | 可以 | 不行 |
| 占多大 | 元素大小 × 长度 | 固定 24 字节（64 位） |

### 3. 切片不是数组，是对数组的一段"视图"

```go
package main

import (
	"fmt"
	"unsafe"
)

func main() {
	a := [3]int{1, 2, 3}
	s := a[1:3] // 从 a 切出来，不复制数据
	s[0] = 88
	fmt.Println(a, s, len(s), cap(s)) // [1 88 3] [88 3] 2 2

	fmt.Println(unsafe.Sizeof(a), unsafe.Sizeof(s)) // 24 24
}
```

改 `s[0]` 就是改 `a[1]`，因为**两者指着同一块内存**。Go 官方博客（Rob Pike，《The mechanics of 'append'》）的原话："A slice is not an array. A slice *describes* a piece of an array."

这里有个容易被误读的巧合：`[3]int` 和 `[]int` 的 `Sizeof` 都是 24。但含义完全不同——**数组的大小跟着长度变**（`[10]int` 就是 80），**切片头永远是 24 字节**（指针 + len + cap 各 8 字节）。所以切片传参很便宜，传数组不是。

切片自己也有长度和容量，而且"改元素生效、改长度不生效"，这是下一篇的主题，这里只要记住：**切片是视图，视图能改内容但改不了原数组的边界**。

### 4. 实际怎么写：参数永远用切片，数组只有两种场合出现

打开任何一个 Go 项目，你几乎看不到数组。原因很实在：数组没法承接长度不确定的输入，而真实业务里长度全是不确定的。

只剩下两种场合：

**① 长度天生固定、固定本身就是约束的东西。** SHA256 摘要 `[32]byte`、IP `[4]byte`、AES 块 `[16]byte`、矩阵 `[3][3]float64`。用数组等于让编译器帮你守着"必须是 32 字节"这条规矩。

**② 需要真正的矩形二维结构。** 数组套数组是连续内存，切片套切片是"每行一个独立分配"，可以参差：

```go
package main

import (
	"encoding/json"
	"fmt"
)

func main() {
	// 矩形：连续内存
	grid := [2][3]int{}
	grid[0], grid[1] = [3]int{1, 2, 3}, [3]int{4, 5, 6}

	// 参差：每行一个独立切片
	var rows [][]int
	rows = append(rows, []int{1, 2, 3})
	rows = append(rows, []int{4})
	fmt.Println(grid[1], rows, len(rows[1])) // [4 5 6] [[1 2 3] [4]] 1

	// nil 切片 vs 空切片：JSON 输出不一样
	var nilS []int
	emptyS := []int{}
	j1, _ := json.Marshal(nilS)
	j2, _ := json.Marshal(emptyS)
	fmt.Println(nilS == nil, emptyS == nil, string(j1), string(j2)) // true false null []
}
```

上面 nil 切片那几行是接口开发的常见事故点：`var list []User` 序列化出来是 `null`，前端 `list.map(...)` 直接崩；`list := []User{}` 或 `make([]User, 0)` 才是 `[]`。

## 落到项目里长什么样

1. **函数参数一律写 `[]T`**：`func Sum(nums []int) int`。写成 `[5]int` 就意味着调用方必须正好凑 5 个，接口直接废掉。
2. **接口返回列表用 `make([]T, 0)`**：nil 切片序列化成 `null` 而不是 `[]`，这是前后端联调最常见的"我这边有数据你那边报错"。
3. **固定长度的协议字段用数组**：签名摘要、UUID 的 `[16]byte`，编译期就能拦住"少传一个字节"。
4. **组合 key 用数组而不是拼字符串**：`map[[2]string]bool` 表示 (type, id) 组合，省掉 `type + ":" + id` 的分隔符冲突问题。
5. **小缓存 key 别用 `fmt.Sprintf`**：几个 int 字段做 key，`map[[2]int]T` 一次哈希搞定，不产生临时字符串。

跟 JS 对照一句：JS 的数组对应 Go 的**切片**（`push` ≈ `append`，`arr.length` ≈ `len(arr)`，`arr.slice(a, b)` ≈ `s[a:b]` 但**不复制**）；Go 的数组在 JS 里没有对应物，它更像 C 的定长数组。

## 常见误解（FAQ）

**❌ 误区1："数组传参是引用传递，函数里改会生效"**

不会。数组是值类型，传参复制整块。实测 `change(a)` 之后原数组一动不动，要改必须 `changePtr(&a)`。Go 里到处见 `*Struct`、`*[]T`，目的不是"引用语义"，而是**省一次复制**。

**❌ 误区2："`[3]int` 和 `[4]int` 可以互相赋值，长度不算类型"**

长度就是类型的一部分，两个类型完全不兼容，编译报 `cannot use a (variable of type [3]int) as [4]int value`。同理 `[3]int` 和 `[]int` 之间也不能直接赋值。

**❌ 误区3："切片是引用类型"**

Go 规范里没有"引用类型"这个分类。切片是**值类型**——一个含指针、长度、容量的描述符，赋值时描述符整个复制。正因为如此，"改元素生效"和"改长度不生效"才能同时成立。叫它"引用类型"最容易记错的就是 `append` 能不能改到调用方。

**❌ 误区4："数组不能比较，只能循环比"**

元素类型可比较，数组就能用 `==` 一次比完。不能比较的是切片（只能跟 `nil` 比）。顺带一条：`[3]int` 能当 map key，`[]int` 不能。

**❌ 误区5："`var a [3]int` 没初始化，里面是脏数据"**

数组的零值是"每个元素都是零值"：`[3]int` 是 `[0 0 0]`，`[3]string` 是 `["" "" ""]`，`[3]bool` 是 `[false false false]`。Go 没有 undefined，也不需要手写清零。

**❌ 误区6："`[]int{}` 和 `var s []int` 是一回事"**

长度和容量都是 0，但一个非 nil、一个 nil。`s == nil` 结果不同，JSON 输出不同（`[]` vs `null`）。判空请用 `len(s) == 0`，两种情况都对。

## 一句话总结

**数组是"定长的值"：长度写进类型，所以赋值复制整块、可以比较、能当 map key；切片是"指向数组某一段的描述符"：只有三个字段的值，所以改元素生效、改长度不生效。再补一句"接口返回列表用 make([]T, 0) 避免 null"，这题就稳了。**
