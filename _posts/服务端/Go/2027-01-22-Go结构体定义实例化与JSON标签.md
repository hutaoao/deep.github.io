## 一句话概括

结构体是 Go 里唯一能自定义的"复合类型"，长得像 TS 的 `interface`，行为却完全相反：**它是值类型，赋值和传参都会整块复制**。

三个最容易按 JS 直觉答错的地方：

- **`b := a` 之后改 `b`，`a` 毫发无伤**——JS 的对象是引用，Go 的结构体是值；
- **字段首字母小写 = 包私有**，外部包连读都读不到，JSON 序列化也会直接跳过它；
- **JSON 标签写错不报错**，`json: "name"` 中间多个空格，编译照过，只是标签静默失效。

面试问结构体，基本不问"怎么定义"，问的全是这三件事。

## 核心知识点

### 1. 定义与四种实例化方式

```go
package main

import "fmt"

type User struct {
	Name string
	Age  int
}

func main() {
	var u1 User              // 零值
	u2 := User{}             // 一样是零值
	u3 := User{"小明", 18}    // 按位置，字段一多就没人看得懂
	u4 := User{Name: "小明"}  // 按键，推荐
	u5 := &User{Age: 20}     // 拿指针

	fmt.Printf("%+v|%+v|%+v|%+v|%+v\n", u1, u2, u3, u4, *u5)
	// {Name: Age:0}|{Name: Age:0}|{Name:小明 Age:18}|{Name:小明 Age:0}|{Name: Age:20}

	// ❌ 按键和按位置不能混着写：
	// bad := User{"小明", Age: 18}
	// 报错：mixture of field:value and value elements in struct literal
}
```

`var u User` 和 `User{}` 完全等价，都是"所有字段取零值"。这就是 Go 不需要构造函数的原因：**结构体从一出生就是可用的**，不存在 JS 里 `new` 之前那个 `undefined` 状态。

不过"可用"要看字段类型：字段是 `map` 的话，零值就是 nil map，写进去照样 panic。这时候老老实实写个 `NewUser()` 去 `make`。

### 2. 结构体是值类型：赋值、传参都是复制

这是和 JS 最大的分歧点，也是面试第一问。

```go
package main

import "fmt"

type User struct {
	Name string
}

func rename(u User)     { u.Name = "changed" }
func renamePtr(u *User) { u.Name = "changed" }

type Point struct{ X, Y int }

func main() {
	a := User{Name: "a"}
	b := a // 整块复制
	b.Name = "b"
	fmt.Println(a.Name, b.Name) // a b —— a 没变

	rename(a)
	fmt.Println(a.Name) // a —— 传参也是复制

	renamePtr(&a)
	fmt.Println(a.Name) // changed —— 传指针才改得动

	// 字段都可比较时，结构体能直接 ==
	fmt.Println(Point{1, 2} == Point{1, 2}) // true

	// 也就能当 map 的 key
	p := Point{1, 2}
	m := map[Point]string{p: "原点"}
	fmt.Println(m[Point{1, 2}]) // 原点
}
```

**答法：Go 里所有传参都是值传递，"引用传递"这个词在 Go 里不存在。指针也是值，只不过这个值是个地址。**

`==` 有个前提：**所有字段都得可比较**。结构体里塞了 slice / map / func 就废了：

```
invalid operation: a == b (struct containing []int cannot be compared)
```

能比较就意味着能当 map key，业务里用「两个字段组成的复合 key」比拼 `"1,2"` 字符串安全——不用担心分隔符和字段内容打架。

### 3. 字段导出：首字母大写才算"公开"

Go 没有 `public` / `private`，只有一条规则：**首字母大写 = 导出（其他包能访问），小写 = 包私有**。

这条规则会直接蔓延到 JSON 上，因为 `encoding/json` 靠反射读字段，反射读不到非导出字段：

```go
package main

import (
	"encoding/json"
	"fmt"
)

type User struct {
	Name     string `json:"name"`
	Password string `json:"-"`
	secret   string // 未导出，外部包读不到，JSON 也不会输出
}

func main() {
	b, _ := json.Marshal(User{Name: "x", Password: "123", secret: "s"})
	fmt.Println(string(b)) // {"name":"x"}

	// 另一个包想读 secret，报错：
	// u.secret undefined (cannot refer to unexported field secret)
}
```

实测输出里 `Password` 和 `secret` 都没了，但原因完全不同：`Password` 是被 `json:"-"` 干掉的，`secret` 是被**小写**干掉的。

顺手一个细节：如果你非要给未导出字段写 json tag，`go vet` 会直接告警 `struct field secret has json tag but is not exported`——这个检查比人眼靠谱。

面试追问"敏感字段怎么不返回给前端"，标准答案是 `json:"-"`——它是显式的，以后改字段名也不会意外漏数据。

### 4. JSON 标签：三种写法 + 两个必踩的坑

标签是字段后面反引号里那串东西，格式 `key:"value"`，**冒号两边不能有空格，多个键之间用空格隔开**。

```go
package main

import (
	"encoding/json"
	"fmt"
)

type User struct {
	ID       int    `json:"id"`             // 改名
	Name     string `json:"name,omitempty"` // 改名 + 空值不输出
	Nick     string `json:",omitempty"`     // 不改名（开头那个逗号），只加选项
	Password string `json:"-"`              // 永远不输出
}

func main() {
	b, _ := json.Marshal(User{ID: 7, Password: "p"})
	fmt.Println(string(b)) // {"id":7}

	b2, _ := json.Marshal(User{ID: 7, Name: "n", Nick: "k"})
	fmt.Println(string(b2)) // {"id":7,"name":"n","Nick":"k"} ← Nick 还是 Go 字段名
}
```

**坑一：`omitempty` 不认结构体的零值。**

文档里 empty 的定义是 `false`、`0`、nil 指针、nil 接口，以及长度为 0 的 array / slice / map / string。**结构体不在这个列表里**，所以零值结构体照样输出：

```go
package main

import (
	"encoding/json"
	"fmt"
)

type Address struct {
	City string `json:"city"`
}

type Zero struct {
	Tags  []string          `json:"tags,omitempty"`
	Meta  Address           `json:"meta,omitempty"`
	Meta2 Address           `json:"meta2,omitzero"`
	Note  string            `json:"note,omitempty"`
}

func main() {
	b, _ := json.Marshal(Zero{})
	fmt.Println(string(b)) // {"meta":{"city":""}}
}
```

实测 `tags`、`note` 都省了，`meta` 却留着一个空对象——前端拿到 `{"city":""}` 还得自己判空。Go 1.24 加了 `omitzero` 专门治这个：它会调类型的 `IsZero()` 方法，没有就按零值判。**要省字段用 `omitzero`，别指望 `omitempty`。**

**坑二：标签写错是静默失败。** 下面这段是反面教材，故意写错：

```go
package main

import (
	"encoding/json"
	"fmt"
)

type User struct {
	Name string `json: "name"` // 冒号后面多了个空格
	Age  int    `json:"age"`
}

func main() {
	b, _ := json.Marshal(User{Name: "x", Age: 1})
	fmt.Println(string(b)) // {"Name":"x","age":1} ← name 没生效
}
```

编译通过、运行不报错，只是 key 没改成功。**`go vet` 能抓住它**，报错原文：

```
struct field tag `json: "name"` not compatible with reflect.StructTag.Get: bad syntax for struct tag value
```

这条值得记——CI 里跑一下 `go vet ./...`，能省掉一次联调。

最后一条：**匿名字段的导出字段会被"提升"到外层**，除非你给它指定了 tag 名字。

```go
package main

import (
	"encoding/json"
	"fmt"
)

type Address struct {
	City string `json:"city"`
}

type Profile struct {
	Nick string `json:"nick"`
}

type User struct {
	ID      int `json:"id"`
	Address     // 没 tag → city 提到顶层
	Profile `json:"profile"` // 有 tag → 变成嵌套对象
}

func main() {
	u := User{ID: 1, Address: Address{City: "杭州"}, Profile: Profile{Nick: "n"}}
	b, _ := json.Marshal(u)
	fmt.Println(string(b)) // {"id":1,"city":"杭州","profile":{"nick":"n"}}
}
```

想让接口扁平就嵌匿名结构体，想分层就加个 tag 名字——写 API 时这个区别很实在。

## 落到项目里长什么样

1. **请求 / 响应 DTO 全靠 tag**：一个结构体同时管序列化和校验（`json:"page,omitempty"` 配 `binding:"required"`），比前端那套 zod schema 少写一半代码。

```go
type UserResp struct {
	ID       uint   `json:"id"`
	Nickname string `json:"nickname"`
	Password string `json:"-"` // 内部有，但永远不出去
}
```

2. **`json:"-"` 守住敏感字段**：密码哈希、内部状态一律打上。比"记得上线前删掉"靠谱得多。
3. **`go vet ./...` 进 CI**：它除了抓 `printf` 参数不匹配，还抓 tag 语法错误和锁的复制问题，Go 项目默认都该跑。
4. **复合 key 用结构体，别拼字符串**：`map[Point]string` 不怕分隔符冲突，也自带类型检查。
5. **先定结构体再写接口**：Go 的结构体 + tag 基本就是一份 OpenAPI 雏形，前端照着写 TS interface，字段名不会两边各写各的。

## 常见误解（FAQ）

**❌ 误区1："结构体是引用类型，赋值之后改一个另一个也会变"**

那是 JS 的对象。Go 的结构体是**值类型**，`b := a` 是整块内存复制，`b.Name = "x"` 完全不影响 `a`。想共享就传 `*User`。

**❌ 误区2："`omitempty` 会把所有零值字段都去掉"**

它只认 `false`、`0`、nil、长度 0 的 array/slice/map/string。**结构体的零值不算空**，给 `Meta` 加 `omitempty` 也依然输出 `{"meta":{"city":""}}`。要省掉得用 Go 1.24 的 `omitzero`。

**❌ 误区3："字段加了 json tag 就会被序列化"**

tag 只负责改名，**能不能序列化看首字母大小写**。小写字段写了 tag 也不会出现在 JSON 里，而且不报错——这是排查"字段怎么丢了"的第一嫌疑。

**❌ 误区4："结构体不能比较，得用 reflect.DeepEqual"**

字段都可比较时 `==` 直接能用，而且比 `DeepEqual` 快得多。只有含 slice / map / func 字段的结构体才不能比，编译器会报 `struct containing []int cannot be compared`。

**❌ 误区5："`json:"name,omitempty"` 和 `json:",omitempty"` 一样"**

不一样。前者把 key 改成 `name`，后者**保留默认的 Go 字段名**，只加选项。少一个逗号就会改掉 key，这种错在 code review 里特别常见。

## 一句话总结

结构体是值不是引用，赋值传参都复制；字段首字母大写才公开，小写连 JSON 都进不去；tag 写错不报错，跑一遍 `go vet` 才看得见。
