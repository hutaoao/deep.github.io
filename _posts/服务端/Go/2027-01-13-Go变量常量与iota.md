## 一句话概括

从前端过来看 Go，最容易犯的错是"按 JS 的直觉理解"：以为 `const` 就是"不能改的变量"、以为没赋值的变量是 `undefined`、以为 `iota` 是个自增变量。

实际上 Go 的设计思路是反过来的——**尽量在编译期就把"可能出问题的地方"掐掉**：

- JS 没有声明就用的变量是 `undefined`，Go 每次声明都会立刻给一个**零值**，永远不存在"未初始化"这个状态；
- JS 的 `const` 只是"绑定不能换"，对象里的内容照样改，Go 的 `const` 是**编译期常量**，连数组都不能是常量；
- `iota` 不是变量，是**常量块里的行号**，理解成"第几行"就全通了。

面试问这块，通常不会问语法怎么写，而是问「Go 为什么不需要 undefined」「const 和 JS 有啥区别」「iota 是怎么算的」。下面按这三条拆。

## 核心知识点

### 1. var 与 :=：类型写在后面，短声明只能在函数里

Go 是"变量名在前、类型在后"，跟 TS 的 `const a: number = 1` 正好相反。好处是类型能整段省略，声明读起来更像自然语言。

```go
var a int = 10        // 完整写法
var b = 10            // 类型推导，b 是 int
var c, d int = 1, 2   // 一行声明多个

func main() {
	e := 10           // := 语法糖，只能在函数内用
	e, f := 20, 30    // ✅ 左边至少有一个新变量，合法
	_ = e
	_ = f
}
```

`:=` 有两条硬规则，都是面试常见的"这么写为什么编译不过"：

```go
// ❌ 包级别不能用 :=
var g = 1
// g2 := 2

// ❌ 左边全是已有变量 → no new variables on left side of :=
func bad() {
	x := 1
	x := 2
	_ = x
}
```

最容易踩的是**变量遮蔽**——`if` / `for` / `switch` 里用 `:=`，会造出一个新的同名变量，外面的那个一点没变：

```go
package main

import (
	"fmt"
	"os"
)

var err error // 包级别，暂时没赋值

func main() {
	if _, err := os.Open("nope.txt"); err != nil { // ⚠️ 这里的 err 是个新变量
		fmt.Println("读取失败", err)
	}
	fmt.Println("外面这个 err:", err) // 永远是 <nil>
}
```

跑一下就知道：里面打印了错误，外面那个 `err` 还是 `<nil>`。新手排查"为什么 err 一直是 nil"，十次有八次是这个原因。想赋值给外层变量，就先用 `var` 声明、里面用 `=`。

### 2. 零值：Go 没有 undefined

```go
func main() {
	var n int            // 0
	var s string         // ""
	var ok bool          // false
	var p *int           // nil
	var m map[string]int // nil

	fmt.Println(n, s == "", ok, p == nil, m == nil) // 0 true false true true
}
```

面试答法：**Go 的变量声明即初始化，编译器会按类型填零值，所以不存在 JS 里 `undefined` 那种"有这个变量但没值"的中间态。** 好处是省掉一堆判空，坏处是 nil 的引用类型用起来有区别：

| 类型 | 零值 | 能不能直接操作 |
| --- | --- | --- |
| `int` / `float64` | `0` | 能 |
| `string` | `""` | 能，`len(s)` 就是 0 |
| `[]T`（切片） | `nil` | **能 append**，`len` 为 0 |
| `map[K]V` | `nil` | 读可以（返回零值），**写直接 panic** |
| `chan T` | `nil` | 收发永久阻塞 |
| `*T`（指针） | `nil` | 解引用 panic |

这里有个高频陷阱：**nil slice 和 nil map 的行为完全不一样**。

```go
func main() {
	var s []int
	s = append(s, 1)    // ✅ 没问题，append 会新建底层数组
	fmt.Println(len(s)) // 1

	var m map[string]int
	// m["a"] = 1        // 💥 panic: assignment to entry in nil map
	m = make(map[string]int)
	m["a"] = 1          // ✅ 先用 make 才能写
	fmt.Println(m["a"]) // 1
}
```

记住一句话：**切片可以"裸奔"，map 必须先 `make`。**

### 3. const：编译期常量，不是"不可变变量"

这是最容易按 JS 直觉答错的地方。Go 的 `const` 只能是**数字、字符串、布尔**这三种（以及它们的运算结果），因为它的值必须在**编译期**就确定下来。

```go
const Pi = 3.14
const Name = "go"
const Max = 1 << 7

// ❌ 编译不过：[]int{…} is not constant
const arr = []int{1, 2}
```

和 JS 的 `const` 摆一起看，差别一目了然：

| | JS 的 `const` | Go 的 `const` |
| --- | --- | --- |
| 能不能改 | 不能重新赋值，但对象的属性可以改 | 编译期就定死，压根没有"赋值"这回事 |
| 支持什么类型 | 任意值（对象、数组、函数都行） | 只有数字、字符串、布尔 |
| 什么时候确定 | 运行时 | 编译期，不占运行时内存 |
| 只读变量 | 有（`const`） | **没有**，只能靠不导出 + 提供方法来保护 |

也就是说：**Go 里没有"C 语言那种 `const int` 只读变量"**。想给前端暴露一个不能改的配置，做法是结构体字段首字母小写（不导出）+ 提供 getter 方法，而不是加 `const`。

另外有个"未类型化常量"的细节值得记：常量不带类型时，编译器会按上下文自动适配，但装不下就报错。

```go
const Big = 1 << 40        // 未类型化常量，本身没有 int32/int64 之分
var a int64 = Big          // ✅ 装得下
// var b int32 = Big       // ❌ cannot use Big ... (overflows)
```

### 4. iota：常量块里的行号计数器

`iota` 只在 `const` 块里出现，值是**当前这一行在块里的索引**（从 0 开始），每遇到一个新 `const` 块就重置。

```go
type OrderStatus int

const (
	StatusPending OrderStatus = iota // 0
	StatusPaid                       // 1
	StatusShipped                    // 2
	StatusDone                       // 3
)
```

三个最常用的套路，面试问"iota 能干嘛"照着说就行：

```go
// ① 跳过某个值：第一个值不用，从 1 开始
const (
	_ = iota // 0 被丢掉
	Low      // 1
	Middle   // 2
)

// ② 带表达式：一次算出 KB / MB / GB
const (
	_  = iota
	KB = 1 << (10 * iota) // 1024
	MB                    // 1048576
	GB                    // 1073741824
)

// ③ 位掩码：一个整数存多种权限
const (
	PermRead   = 1 << iota // 1
	PermWrite              // 2
	PermDelete             // 4
)

func main() {
	perm := PermRead | PermWrite
	fmt.Println(perm&PermRead != 0, perm&PermDelete != 0) // true false
}
```

有两个细节必须弄清楚，否则面试一问就露馅：

1. **iota 是行号，不是"每行 +1 的变量"。** 空行和注释不占号，所以加注释不影响数值。
2. **省略表达式的行会重复上一行的表达式。** 所以中间插一行别的表达式，后面的值会跟着变：

```go
const (
	A = iota // 0
	B        // 1
	C = 100  // 100
	D        // 100 ← 重复 C 的表达式，不是 3
	E        // 100
)
```

实测输出就是 `0 1 100 100 100`。这一点和"iota 会继续自增"的直觉正好相反。

## 落到项目里长什么样

1. **配置默认值**：`var cfg Config` 拿来就是一个"全零但可用"的结构，数字是 0、字符串是空，不用像 JS 那样每层判 `undefined`。
2. **订单 / 任务状态**：`type OrderStatus int` 配 iota，比前端那套 `const STATUS = { 1: '待支付' }` 多了一层编译期检查——传错类型编译就过不去。
3. **权限位掩码**：`if perm&PermWrite != 0`，一个 int 存读/写/删三种权限，数据库里一列就够了，不用关联表。
4. **文件大小单位**：`KB/MB/GB` 用 `1 << (10 * iota)` 一行写完，比手写 `1048576` 不容易数错零。
5. **前后端状态码对齐**：把状态常量集中在一个 `const.go` 里，前端 TS 的类型定义照抄一份，避免两边各写各的、对不上。

## 常见误解（FAQ）

**❌ 误区1："Go 的 const 和 JS 的 const 一样，就是不能改的变量"**

Go 的 `const` 是**编译期常量**，只支持数字、字符串、布尔，`const arr = []int{1, 2}` 直接编译不过。Go 里根本没有"不可变变量"这种东西，想保护数据只能靠不导出字段 + 方法封装。

**❌ 误区2："var 声明了不赋值，就是 nil"**

基本类型是零值不是 nil：`int` 是 0、`string` 是 `""`、`bool` 是 `false`。只有切片、map、chan、指针、接口这些才是 nil。所以 `var s string` 之后直接 `len(s)` 拿到 0，不会像 JS 那样碰到 `undefined`。

**❌ 误区3："nil 的 slice 和 nil 的 map 差不多，都不能用"**

正相反。nil slice 可以 `append`，Go 会自动给你分配底层数组；nil map **写就 panic**（`assignment to entry in nil map`），读才返回零值。要用 map 必须先 `make`。

**❌ 误区4："iota 是个自增变量，每行都会 +1"**

它是**行号**：每个 const 块从 0 重新算，空行注释不占号；中间某行写了别的表达式，后面省略表达式的行会重复那一行，值就"卡住不动"了。上面 `A/B/C/D/E` 输出 `0 1 100 100 100` 就是活证据。

**❌ 误区5："Go 会像 JS 那样自动做类型转换"**

不会。`int32 + int64` 直接编译报错 `mismatched types`，必须显式 `int64(a)`。唯一的例外是**未类型化常量**，编译器会按上下文帮你适配，但装不下就报 `overflows`。

## 一句话总结

Go 没有 undefined，声明就有零值；常量是编译期的死值，连数组都不算；iota 是行号不是自增变量——这三句记住，Go 基础题就对一半。
