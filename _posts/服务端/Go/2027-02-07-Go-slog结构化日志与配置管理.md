## 一句话概括

`fmt.Println` 调试、`log.Printf` 打字符串，这两种在前端叫 `console.log`，上线就得换掉。Go 1.21 开始标准库给了 `log/slog`，做的事情就一件：**让每条日志变成"一条消息 + 一组 key-value + 一个级别"**，而不是一句拼好的字符串。

为什么面试问它？因为日志是"出事之后唯一能看的东西"，而能不能按 `user_id=42` 过滤、能不能只把 ERROR 拉去告警，完全取决于你当初打的是字符串还是结构化字段。

配置管理是同一道题的另一半：**代码里不能写死数据库密码**，所以配置得从环境变量和文件来。这两件事在真实项目里通常写在同一个 `main.go` 开头，就一起讲了。

## 核心知识点

### 1. `log` 只是 println，`slog` 才是日志

老的 `log` 包没有级别，也没有字段，你能做的就是把所有东西 `Sprintf` 进一句话里。`slog` 一行代码就带上了级别和多个 key-value：

```go
package main

import "log/slog"

func main() {
	slog.Info("服务启动", "port", 8080, "env", "dev")
	slog.Debug("默认级别是 Info，这句看不到")
	slog.Info("参数少写了一个", "user_id")
}
```

输出（时间戳省略）：

```text
INFO 服务启动 port=8080 env=dev
INFO 参数少写了一个 !BADKEY=user_id
```

三个信息点：

1. **默认 handler 输出的是 `key=value` 文本**，后面带级别 `INFO`；
2. **默认最低级别是 Info**，所以 `slog.Debug` 什么都不打——这是新手"我明明写了日志怎么没有"的第一大原因；
3. key-value 必须**成对**。少一个值，剩下的那个 key 就会被写成 `!BADKEY=user_id`。看到 `!BADKEY` 就是参数个数写错了，非常好认——而且 `go vet` 会静态报出来：`call to slog.Info missing a final value`。

面试口述：**slog 的每条日志是一个 `Record`——time、level、msg，加上你传进来的 key-value 属性列表；handler 决定这个 Record 最终长成文本还是 JSON。**

写法上还有个细节：`slog.Info("登录", "user", "ada")` 这种裸 key-value 最省事，但类型会退化成 `any`；**追求零分配和类型正确就用 `slog.String` / `slog.Int64` / `slog.Duration`** 这些构造函数。

### 2. Handler 决定长什么样，level 决定谁该出现

`slog` 把"记录什么"和"输出成什么格式"拆开了，这是它和 `log` 最本质的区别。内置两个 handler：

| Handler | 输出 | 用在哪 |
| --- | --- | --- |
| `slog.NewTextHandler` | `time=... level=INFO msg=... k=v` | 本地开发，人眼看 |
| `slog.NewJSONHandler` | 一行一个 JSON | 线上，给 Loki / ELK / 云日志直接解析 |

换成 JSON 只要换 handler，业务代码一个字不用改：

```go
package main

import (
	"log"
	"log/slog"
	"os"
)

func main() {
	slog.SetDefault(slog.New(slog.NewJSONHandler(os.Stdout, nil)))

	slog.Info("登录成功", "user", "ada", "attempts", 3)
	log.Printf("老的 log 包也被接管了")
}
```

输出（时间戳略）：

```text
{"time":"...","level":"INFO","msg":"登录成功","user":"ada","attempts":3}
{"time":"...","level":"INFO","msg":"老的 log 包也被接管了"}
```

注意第二行：**`slog.SetDefault` 之后，项目里原有的 `log.Printf` 也会走 slog 的 handler**。这是老项目渐进式迁移的省事做法——不用一次性把几百处 `log.Printf` 全改掉。

级别控制的正确姿势是 `slog.LevelVar`，因为它能**运行时改**（配个 debug 接口或者收到信号就调低），而不是写死一个常量：

```go
package main

import (
	"log/slog"
	"os"
)

func main() {
	lv := new(slog.LevelVar) // 零值就是 Info
	h := slog.NewJSONHandler(os.Stdout, &slog.HandlerOptions{Level: lv})
	logger := slog.New(h).With("service", "order")

	logger.Debug("现在是 Info 级，看不到")
	lv.Set(slog.LevelDebug)
	logger.Debug("调低之后出来了")

	reqLog := logger.With("request_id", "abc-123")
	reqLog.Info("下单成功", slog.Int64("order_id", 1001), slog.Group("user", "id", 7))
}
```

输出（时间戳略）：

```text
{"time":"...","level":"DEBUG","msg":"调低之后出来了","service":"order"}
{"time":"...","level":"INFO","msg":"下单成功","service":"order","request_id":"abc-123","order_id":1001,"user":{"id":7}}
```

这里有两个必须会的用法：

- **`logger.With(...)`** 生成一个带固定字段的子 logger。每个请求开头 `reqLog := logger.With("request_id", id)`，后面这个请求的所有日志都自带 request_id，排查问题直接搜一个 ID 串起全链路。这就是前端 `axios` 拦截器统一加 header 的服务端版本。
- **`slog.Group`** 把字段收成嵌套对象，JSON 里变成 `"user":{"id":7}`。字段多的时候用它会整齐很多。

### 3. 配置从哪来：env 优先，文件兜底

配置这道题的标准答案是 12-Factor 的那句话：**配置存在环境变量里，代码跟环境无关**。所以覆盖顺序固定是：

**代码默认值 < 配置文件 < 环境变量**（有些项目还会把命令行参数放最上面，但服务端基本不用）。

为什么 env 优先？因为 Dockerfile 和 K8s 改环境变量只要重启 pod，不用重新打镜像、不用改挂载的配置文件。测试环境想连测试库，改一个 `SHOP_DB_DSN` 就够了。

读环境变量最容易错的地方是 **`os.Getenv` 分不清"没设置"和"设置成空串"**：

```go
package main

import (
	"fmt"
	"os"
	"strconv"
)

func envInt(key string, def int) int {
	s, ok := os.LookupEnv(key)
	if !ok {
		return def
	}
	if n, err := strconv.Atoi(s); err == nil {
		return n
	}
	return def
}

func main() {
	os.Setenv("PORT", "9000")
	os.Unsetenv("TIMEOUT")

	fmt.Println(envInt("PORT", 8080), envInt("TIMEOUT", 30))
	fmt.Println(os.Getenv("TIMEOUT") == "") // true：到底没设，还是设成了空串？
}
```

输出：

```text
9000 30
true
```

两个结论：**判断"有没有配"用 `os.LookupEnv` 的第二个返回值**；`strconv.Atoi` 失败时别把 0 当成配置值传下去，要退回默认值或直接报错退出。

### 4. 用 Viper 把两个来源合起来

上一步是手写，配置项少还行；一旦有嵌套结构（db / redis / jwt 各一组），就该上 Viper 了。面试只需要会说这四步：**指定文件 → 读文件 → 开环境变量自动映射 → Unmarshal 进结构体**。

先给一个 `config.yaml`：

```yaml
env: dev
port: 8080
db:
  dsn: root@tcp(127.0.0.1:3306)/shop
```

```go
package main

import (
	"fmt"
	"log/slog"
	"os"
	"strings"

	"github.com/spf13/viper"
)

type Config struct {
	Env  string `mapstructure:"env"`
	Port int    `mapstructure:"port"`
	DB   struct {
		DSN string `mapstructure:"dsn"`
	} `mapstructure:"db"`
}

func Load(path string) (*Config, error) {
	v := viper.New()
	v.SetConfigFile(path)
	v.SetConfigType("yaml")

	v.SetDefault("env", "prod") // 优先级最低：默认值
	v.SetDefault("port", 9000)

	if err := v.ReadInConfig(); err != nil { // 第二层：配置文件
		return nil, fmt.Errorf("读配置: %w", err)
	}

	v.SetEnvPrefix("SHOP") // 环境变量写成 SHOP_ENV / SHOP_PORT
	v.SetEnvKeyReplacer(strings.NewReplacer(".", "_"))
	v.AutomaticEnv() // 优先级最高：环境变量

	var cfg Config
	if err := v.Unmarshal(&cfg); err != nil {
		return nil, fmt.Errorf("解析配置: %w", err)
	}
	return &cfg, nil
}

func main() {
	os.Setenv("SHOP_ENV", "staging")

	cfg, err := Load("data/config.yaml")
	if err != nil {
		slog.Error("配置加载失败", "err", err)
		os.Exit(1)
	}
	slog.Info("配置就绪", "env", cfg.Env, "port", cfg.Port, "dsn", cfg.DB.DSN)
}
```

输出（时间戳省略）：

```text
INFO 配置就绪 env=staging port=8080 dsn=root@tcp(127.0.0.1:3306)/shop
```

看结果就知道覆盖关系：`env` 被 `SHOP_ENV` 改成了 `staging`，`port` 文件里写了 8080 所以默认的 9000 没用上，`db.dsn` 来自文件。

**这里有个真实的坑**：`AutomaticEnv()` 配 `Unmarshal` 的时候，**如果某个配置项在默认值和配置文件里都不存在，那环境变量也读不进来**。原因是 `Unmarshal` 拿的是 Viper "已知的所有键"（默认值 + 配置文件 + 显式 `Set` 过的），而 `AutomaticEnv` 只影响 `Get` 这条路径，不会把环境变量登记进这个已知集合：

```go
package main

import (
	"fmt"
	"os"
	"strings"

	"github.com/spf13/viper"
)

type Config struct {
	LogLevel string `mapstructure:"log_level"` // 配置文件里没有这一项
}

func main() {
	os.Setenv("SHOP_LOG_LEVEL", "debug")

	v := viper.New()
	v.SetConfigFile("data/config.yaml")
	v.SetConfigType("yaml")
	_ = v.ReadInConfig()
	v.SetEnvPrefix("SHOP")
	v.SetEnvKeyReplacer(strings.NewReplacer(".", "_"))
	v.AutomaticEnv()

	var cfg Config
	_ = v.Unmarshal(&cfg)
	fmt.Printf("Unmarshal=%q GetString=%q\n", cfg.LogLevel, v.GetString("log_level"))
}
```

实测输出就是这么一个反差：`Unmarshal` 拿到空串，`GetString` 能拿到 `debug`。**解法是给这个 key 补一行 `v.SetDefault("log_level", "info")`**，让 Viper 先"认识"它。这个坑不踩过一次基本想不到。

## 落到项目里长什么样

1. **`main` 开头两件事：`InitLogger()` 和 `LoadConfig()`**。顺序很重要——先有 logger，配置读失败的时候才能打出结构化错误。
2. **handler 由环境决定**：`env == "dev"` 用 TextHandler，否则 JSONHandler。一行 if，本地看得舒服、线上机器能解析。
3. **HTTP 中间件里挂 request_id**：`logger.With("request_id", r.Header.Get("X-Request-ID"))`，再把 status 和耗时一起打。前端在 `fetch` 拦截器里生成并透传这个 ID，出问题两边对得上。
4. **敏感配置只走环境变量**：`config.yaml` 提交进仓库（它只有非敏感默认值），`config.local.yaml` 加进 `.gitignore`，密码和 JWT 密钥通过 `SHOP_DB_PASSWORD` 这类 env 注入。等价的运维做法就是 K8s 的 ConfigMap + Secret。
5. **配置加载完立刻校验**：端口范围、DSN 非空、密钥长度够不够，缺一个就 `slog.Error` + `os.Exit(1)`。别等服务跑起来、第一个请求进来才发现连不上库。

跟前端对照一下就很清楚：前端 `console.log('user', user)` 对应 `logger.Info("用户登录", "user_id", u.ID)`；前端的 Sentry breadcrumb 里那一串结构化字段，就是服务端日志平台里你能 filter 的 key。**能 filter 的日志才叫日志，剩下的都叫打印。**

## 常见误解（FAQ）

**❌ 误区1："slog 得 `go get` 装一下"**

`slog` 是 **Go 1.21 起的标准库**，import 路径是 `log/slog`，不用装任何依赖。它的定位正是取代 `log`，同时让 zap / zerolog 这些第三方库不再是必选项——量级不大时标准库完全够用。

**❌ 误区2："key-value 随便传，反正都能打出来"**

必须成对。奇数个参数时多出来的那个 key 会变成 `!BADKEY=xxx`（实测原文），值直接丢失。字段多、容易数错的地方，用 `slog.String(...)` / `slog.Int(...)` 类型化写法，参数个数一目了然。

**❌ 误区3："线上日志打成文本就行，反正能看懂"**

线上日志是给机器读的。`msg="登录成功" user=ada` 这种文本只能正则去抠字段，而 JSON 一行一条，Loki / ELK 能直接按 `user="ada"` 过滤、按 `level="ERROR"` 告警。**开发用文本、线上用 JSON，用环境变量切换**，这是标准做法。

**❌ 误区4："`os.Getenv` 返回空串，就是没配置"**

也可能是配置了、但值就是空串。要靠 `os.LookupEnv(key)` 的第二个返回值 `ok` 来区分。这个区别在"密码允许为空"和"密码必须给"这种场景下会直接决定启动成功还是失败。

**❌ 误区5："配置在 `config.yaml` 里写死最省事，环境不同就改文件"**

文件一旦提交进仓库，所有环境共用一份，最后必然演变成 `if env == "prod" { ... }` 这种分支写在代码里——这正是 12-Factor 要避免的。**代码只认字段，值从外面来**；同一份二进制能在测试和生产跑，才是能用的配置管理。

## 一句话总结

`slog` 把日志从"一句话"变成"一条带级别和字段的记录"，`SetDefault + JSONHandler` 两行就能上线；配置永远按"默认值 < 文件 < 环境变量"覆盖，敏感信息只走 env——这两件事都是面试官一听就知道你有没有真上过线的问题。
