## 一句话概括

`type` 有两种写法，面试就爱考这一字之差：

```go
package main

import "fmt"

type Age int    // 类型定义：造一个全新的类型 Age
type Age2 = int // 类型别名：int 的另一个名字，本质还是 int

func main() {
	var a Age = 25
	var b Age2 = 30
	fmt.Printf("%T 和 %T\n", a, b) // main.Age 和 int
}
```

- 有 `=` 是**别名**：`Age2` 和 `int` 是同一个类型，随便赋值，`%T` 打印出来还是 `int`；
- 没 `=` 是**新类型**：`Age` 是个独立的类型，跟 `int` 不能直接赋值，必须 `Age(n)` 显式转换。换来的是能挂方法、能做类型安全。

为什么面试问它？因为 Go 是**名义类型（nominal typing）**——名字不同就是不同类型，跟 TS 那种"结构一样就算一样"正好相反。你写 `type UserID int64` 和 `type OrderID int64`，编译器就真的不让这俩互相赋值，这是 Go 里最便宜的一层防呆。

记住一句：**带等号是改名，不带等号是造新生。**

## 核心知识点

### 1. 差一个等号，差的是一个"身份"

```go
package main

import (
	"fmt"
	"reflect"
)

type Age int        // 新类型
type AliasAge = int // 别名

func main() {
	var a Age = 25
	var b AliasAge = 30
	var n int = 40

	fmt.Printf("%T %T %T\n", a, b, n) // main.Age int int
	fmt.Println(reflect.TypeOf(a))    // main.Age

	b = n      // ✅ 别名就是 int，直接赋
	n = b      // ✅ 反过来也行
	a = Age(n) // ✅ 新类型必须显式转换
	// a = n   // ❌ cannot use n (variable of type int) as Age value in assignment
	fmt.Println(a, b, n) // 40 40 40
}
```

实测输出就是 `main.Age int int`。**`%T` 是最快的自检方式**：打印带包名前缀（`main.Age`）的是新类型，只打印 `int` 的是别名。

两个新类型之间也不能直接赋值，哪怕底层一模一样：

```go
package main

import "fmt"

type Age int
type Month int

func main() {
	var a Age = 10
	var m Month = 1
	// m = a       // ❌ cannot use a (variable of int type Age) as Month value in assignment
	m = Month(a)   // ✅ 底层都是 int，能显式转换
	fmt.Println(m) // 10
}
```

留意报错文案：`variable of int type Age`——括号里把**底层类型**和**定义类型**都写出来了。Go 1.27 的这版文案很好用，一眼就知道"虽然它底层是 int，但它现在叫 Age"。

### 2. 新类型不继承方法，别名完全共享

`bytes.Buffer` 是最好的例子：别名拿到全套方法，新类型一个都没有。

```go
package main

import (
	"bytes"
	"fmt"
)

type BufAlias = bytes.Buffer // 别名：就是 bytes.Buffer 本身
type BufDef bytes.Buffer     // 新类型：方法集是空的

func main() {
	var a BufAlias
	a.WriteString("hi") // ✅ 方法都在
	fmt.Println(a.String())

	var d BufDef
	// d.WriteString("hi") // ❌ d.WriteString undefined (type BufDef has no field or method WriteString)
	d = BufDef(*bytes.NewBufferString("yo"))
	raw := bytes.Buffer(d) // 想用回原方法，只能转回去
	fmt.Println(raw.Len()) // 2
}
```

反过来，**你不能给别名加方法**：

```go
package main

import "fmt"

type Age = int // Age 就是 int

// func (a Age) Foo() {} // ❌ cannot define new methods on non-local type Age

func main() {
	var a Age = 1
	fmt.Println(a + 1) // 2，因为 a 就是 int
}
```

报错里写的是 `Age`，但编译器真正指的是 `int`——`int` 不是本包定义的类型，Go 不允许给它挂方法。这也正是 `http.HandlerFunc` 必须写成 `type HandlerFunc func(ResponseWriter, *Request)`（新类型）而不是别名的原因：只有新类型才能拥有 `ServeHTTP` 方法，才能当 handler 用。

一个冷知识：如果别名指向的是**本包定义**的类型，那给别名写方法是给原类型写，能过编译（因为是同一个类型）。但这么写读起来像给别名加方法，实际坑人，别干。

### 3. 转换规则：什么时候必须转、什么时候转不了

三条，背下来就够：

1. 别名**不用转**，因为它就是原类型；
2. 新类型 ↔ 它的底层类型：**必须转**，而且因为底层相同所以总能转；
3. 两个不同的新类型之间：只要底层相同，**也能转**。

转不了的坑在复合类型上——切片不能整体转：

```go
package main

import "fmt"

type Age int
type Month int

func main() {
	nums := []int{1, 2, 3}
	// ages := []Age(nums) // ❌ cannot convert nums (variable of type []int) to type []Age

	ages := make([]Age, len(nums)) // 只能逐个转
	for i, v := range nums {
		ages[i] = Age(v)
	}
	fmt.Println(ages) // [1 2 3]

	var a Age = 10
	var m Month = Month(a) // 两个新类型底层都是 int → 能转
	fmt.Println(a, m)      // 10 10
}
```

原因很直白：转换的前提是"底层类型相同"，而 `[]Age` 和 `[]int` 的**元素类型**就不一样，两个切片的底层类型自然不同。想要批量换，就老老实实循环（或者上泛型写个 `Map`）。

还有一个常见疑问：**新类型还能不能做加减？**

```go
package main

import "fmt"

type Age int

func main() {
	var a Age = 10
	var n int = 1
	_ = n // 先声明着，下面演示为什么它加不进去

	fmt.Println(a + 1)      // 11，未类型化常量会适配 Age
	fmt.Printf("%T\n", a+1) // main.Age，结果还是 Age
	// fmt.Println(a + n)   // ❌ invalid operation: a + n (mismatched types Age and int)
}
```

区别在**常量还是变量**：字面量 `1` 是未类型化常量，编译器会按上下文把它变成 `Age`，所以能加；`n` 是 `int` 变量，类型已经定死了，`Age + int` 直接编译报错。

### 4. 什么时候用哪个（顺带记住 byte/rune/any 都是别名）

**用新类型**，当你要"类型安全"或者"要挂方法"：

- ID 防串：`type UserID int64` / `type OrderID int64`；
- 枚举：`type OrderStatus int` + iota + `String()`；
- 给 `string` 包一层做校验：`type Phone string`。

**用别名**，当你要"只是换个名字"：

- 渐进式迁移——这正是 Go 1.9 引入别名的原始动机：把类型从 A 包搬到 B 包，A 包里留一句 `type Old = b.New`，所有调用方一行都不用改；
- 给长类型起短名：`type Handler = func(w http.ResponseWriter, r *http.Request)`；
- 泛型别名（Go 1.24 起）：`type Set[T comparable] = map[T]struct{}`，1.27 上实测能编译。

表拉一下，一眼看清：

| | `type A B`（新类型） | `type A = B`（别名） |
| --- | --- | --- |
| 是不是新类型 | 是，有独立身份 | 不是，就是 B |
| 和 B 能否直接赋值 | 不能，要 `A(x)` | 能 |
| 方法集 | 空的，得自己定义 | 和 B 完全一样 |
| 能否挂方法 | 能 | 不能（B 不在本包时） |
| `%T` 打印 | `main.A` | B 的名字 |
| 典型用途 | 类型安全、枚举、挂方法 | 迁移、起短名 |

最后补一个很能说明问题的细节：**`byte`、`rune`、`any` 本身就是别名**——`byte = uint8`、`rune = int32`、`any = interface{}`。所以 `reflect.TypeOf(byte(1)).Name()` 实测是 `uint8`，`rune('a')` 是 `int32`。这就解释了一个经典现象：`[]byte` 和 `[]uint8` 是同一个类型，函数参数写哪个都行。

## 落到项目里长什么样

1. **ID 防串**：`type UserID int64`、`type OrderID int64`，接口参数传错编译器直接拦，比写注释管用一百倍。
2. **金额单位**：`type Cents int64`，团队里没人会把"元"传进来，也不会有人把 `100.5` 塞给一个整数。
3. **状态枚举**：`type OrderStatus int` 配 iota，再加个 `func (s OrderStatus) String() string`，日志里直接打印中文状态，而不是 `status=3`。
4. **给 string 包一层校验**：`type Phone string` 配 `func (p Phone) Valid() bool`，比每个 handler 里各写一遍正则好维护。
5. **包迁移留后门**：把 `pkg/user.User` 搬到 `pkg/account.User` 时，在 user 包里留 `type User = account.User`，调用方零改动，等大家迁完再删。

## 常见误解（FAQ）

**❌ 误区1："`type A = B` 和 `type A B` 差不多，就是写法不同"**

差远了。前者只是起个外号，`A` 和 `B` 是同一个类型，随便赋值、方法共享；后者造了个新类型，必须显式转换，方法集是空的。判断方法就一条：`%T` 打印出来是不是原类型名。

**❌ 误区2："新类型只是换个名字，原来的方法应该还在"**

不继承。`type BufDef bytes.Buffer` 之后，`BufDef` 一个方法都没有，`d.WriteString` 直接编译不过。要用回原方法就 `bytes.Buffer(d)` 转回去。

**❌ 误区3："可以给别名加方法，这样就能给 int 加方法了"**

不行。报错是 `cannot define new methods on non-local type Age`——别名不是新类型，而 `int` 又不是本包的东西。想给 `int` 加方法，唯一办法就是 `type MyInt int`，然后忍受每次都要转换。

**❌ 误区4："`type Age int` 之后，`age + 1` 会报类型不匹配"**

不会。`1` 是未类型化常量，编译器会按上下文把它转成 `Age`，`a + 1` 输出 `11` 且结果类型还是 `main.Age`。只有当你加的是 `int` **变量**时才会报 `mismatched types Age and int`。这个区分面试官很爱追问。

**❌ 误区5："两个新类型底层一样，可以随便赋值"**

只能显式转换，不能直接赋值。`type Age int` 和 `type Month int` 之间必须写 `Month(a)`。这正是它存在的价值——如果随便赋值，那这层类型安全就白加了。

## 一句话总结

带等号是给旧类型改名（同一个东西，方法全继承），不带等号是造新类型（独立身份，要转换、能挂方法）——一个等号，决定了编译器把不把你当外人。
