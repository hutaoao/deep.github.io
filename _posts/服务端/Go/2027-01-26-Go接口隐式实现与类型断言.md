## 一句话概括

Go 的接口跟 Java / TS 长得像，用起来是另一套逻辑：**没有 implements，你把方法写全了就算实现了**。

面试问接口基本就四件事：

- 为什么不需要 implements，这么设计好在哪；
- 值接收者和指针接收者，谁能装进接口；
- `any` 到底是啥、类型断言该怎么写；
- 一个 nil 指针装进接口之后，为什么接口不等于 nil。

最后那条是分水岭，答对的基本就算懂 Go 了。下面按这四条拆。

## 核心知识点

### 1. 隐式实现：方法写全了就算实现

接口就是一张"方法签名清单"。任何类型只要方法一模一样，编译器就认为它实现了这个接口，不需要任何声明。

```go
package main

import "fmt"

type Speaker interface {
	Speak() string
}

type Dog struct{ Nick string }

// 没有 implements，没有注册，写完就是实现了
func (d Dog) Speak() string { return d.Nick + ": 汪汪" }

func main() {
	var s Speaker = Dog{Nick: "大黄"}
	fmt.Println(s.Speak()) // 大黄: 汪汪
}
```

好处一句话就能说完，面试直接照这个说：

> 因为接口是隐式实现的，我可以在**调用方**定义"我只需要一个 Speak 方法"，而不用去改实现方的代码。标准库的 `io.Reader` 就是这么用的——一个类型只要有个 `Read([]byte) (int, error)`，就能塞进任何接受 Reader 的地方，谁也没给它加过 implements。

由此带出三条工程习惯，说出来就是加分项：

- **谁用谁定义接口**，别在实现包里建个 `IUserService` 大全集；
- **接口越小越好**，1–3 个方法，`io.Reader` 就一个；
- **函数收接口、返回具体类型**（accept interfaces, return structs）——收接口方便替换和 mock，返回具体类型让调用方拿到完整方法集。

隐式实现有个副作用：**写错了不会当场报，只在赋值那一刻报**。所以推荐在实现处加一行编译期断言，对不上立刻炸：

```go
package main

type Animal interface{ Speak() string }

type Cat struct{}

func (c *Cat) Speak() string { return "喵" }

// 编译期断言：类型对不上，这个包直接编不过
var _ Animal = (*Cat)(nil)

func main() {
	var a Animal = &Cat{}
	println(a.Speak())
}
```

`var _ Animal = ...` 里的 `_` 意思是"我只要检查，不要这个变量"，这是 Go 里检查"有没有实现"的标准写法。

**方法集规则（必考）**：能不能装进接口，取决于接收者是谁。

| 方法定义在哪 | `T` 能装进接口吗 | `*T` 能装进接口吗 |
| --- | --- | --- |
| 值接收者 `func (t T) M()` | ✅ 能 | ✅ 能 |
| 指针接收者 `func (t *T) M()` | ❌ 不能 | ✅ 能 |

原因一句话：**指针的方法集包含值的所有方法，反过来不成立**。`*T` 能调 `T` 的值接收者方法（Go 自动帮你解引用），但 `T` 拿不到指针接收者方法——它没有稳定地址可给。

（跟《方法接收者》那篇角度不同：那篇讲"改了原对象到底生效没"，这篇只讲"能不能装进接口"。）

真实报错长这样（本机 go1.27.2 实测）：

```
cannot use Cat{…} (value of struct type Cat) as Animal value in variable declaration:
Cat does not implement Animal (method Speak has pointer receiver)
```

报错已经把话说全了：**method Speak has pointer receiver**。

### 2. any：所有类型都满足的空接口

空接口没有方法要求，所以**任何类型都算实现了它**。Go 1.18 给它起了个短名字 `any`——它俩完全是同一个东西，`any` 是 `interface{}` 的**类型别名**，不是新类型。

```go
package main

import "fmt"

func printAny(v any) {
	fmt.Printf("%v (%T)\n", v, v)
}

func main() {
	printAny(1)           // 1 (int)
	printAny("hi")        // hi (string)
	printAny([]int{1, 2}) // [1 2] ([]int)

	// 别名，随便换着写
	var a any = 1
	var b interface{} = 1
	fmt.Println(a == b) // true
}
```

项目里 `any` 无处不在：`fmt.Println` 的参数是 `...any`、`json.Unmarshal` 的目标是 `any`、`map[string]any` 就是前端那个 `Record<string, any>`。

代价很直接：**塞进 any 之后编译期就不知道它是什么了**，要用必须断言回来。所以现在的共识是——只是想"泛型地用一下"，优先用泛型（`[T any]`）；`any` 留给类型真未知的场景（反射、JSON、日志）。

### 3. 类型断言与 type switch：把东西从 any 里掏出来

两种写法，**线上代码一律用带 ok 的那个**：

```go
package main

import "fmt"

func main() {
	var v any = "hello"

	// ✅ 带 ok：类型不对返回零值 + false，不 panic
	s, ok := v.(string)
	fmt.Println(s, ok) // hello true

	n, ok := v.(int)
	fmt.Println(n, ok) // 0 false

	// ❌ 单返回值：类型不对直接 panic
	// m := v.(int)
	// panic: interface conversion: interface {} is string, not int
}
```

单返回值那个 panic 文案值得背一下：`interface conversion: interface {} is string, not int`。如果值是 nil，就是 `interface conversion: interface {} is nil, not string`。

还有一种更早的拦截——**断言到"根本不可能实现这个接口"的类型时，编译器直接不让你过**：

```go
package main

type Animal interface{ Speak() string }

type Dog struct{}

func (d Dog) Speak() string { return "woof" }

func main() {
	var a Animal = Dog{}
	n := a.(int) // 编译报错，跑都跑不起来
	_ = n
}
```

```
impossible type assertion: a.(int)
	int does not implement Animal (missing method Speak)
```

`int` 永远不可能有 `Speak()` 方法，断言必然失败，编译器就提前拦了。只有断言到 `any` 或者"有可能实现该接口"的类型，才会留到运行时。

**type switch**：一次问多个类型，比连写几个 `if _, ok := ...` 干净得多。

```go
package main

import "fmt"

func describe(v any) string {
	switch x := v.(type) {
	case nil:
		return "nil"
	case string:
		return "string:" + x // 这个分支里 x 是 string
	case int, int64:
		return fmt.Sprintf("number %T", x) // 多个类型合写，x 还是 any
	case error:
		return "error:" + x.Error()
	default:
		return fmt.Sprintf("other %T", v)
	}
}

func main() {
	fmt.Println(describe("abc"))              // string:abc
	fmt.Println(describe(int64(1)))           // number int64
	fmt.Println(describe(fmt.Errorf("boom"))) // error:boom
	fmt.Println(describe(nil))                // nil
}
```

两个细节：

1. **单个类型的 case 里，`x` 已经是那个类型**，能直接调它的方法；**多类型合写的 case 里 `x` 还是 `any`**，得再断言一次。
2. `case nil` 判断的是"接口本身是 nil"，跟 `case *SomeType` 不是一回事。

type switch 从上往下匹配，第一个命中就停，所以 `interface{}` 这种宽泛的 case 要放最后。

### 4. 最经典的坑：nil 接口 ≠ 接口里装着 nil

接口变量在内存里是**两个字**：一个字记"动态类型"，一个字记"动态值"。**只有两个都是 nil，接口才等于 nil**。

```go
package main

import "fmt"

type Animal interface{ Kind() string }

type Cat struct{ Nick string }

func (c *Cat) Kind() string { return "cat" }

func main() {
	var c *Cat // c 是 nil 指针
	var a Animal = c

	fmt.Println("接口 == nil ?", a == nil) // false
	fmt.Println("指针 == nil ?", c == nil) // true
	// 方法体没碰字段，nil 接收者也照样能跑
	fmt.Println(a.Kind()) // cat
}
```

`a` 的类型字是 `*Cat`（非 nil），值字才是 nil，所以 `a == nil` 是 false。顺带一个细节：调 `a.Kind()` 不会崩——`Kind()` 的方法体里没碰任何字段，接收者是 nil 也无所谓；要是方法体里访问了 `c.Nick`，那就变成解引用 nil，直接 panic。

这个坑在 `error` 上最致命：函数想表达"查无此人不算出错"，返回了一个 nil 的错误指针，`err == nil` 就成了 false，调用方一路带着这个假错误往上跑，最后日志里出现一条 `<nil>` 的错误。修法只有一条——**要表示没出错就写 `return nil`，别把 nil 指针往接口里塞**，错误处理那块下一篇专门讲。

## 落到项目里长什么样

1. **Service 层用接口做可替换**：`type UserStore interface { Get(ctx context.Context, id int64) (*User, error) }`，生产传 MySQL 实现，单测传内存 map，handler 一行不改。
2. **HTTP 中间件**：`http.Handler` 就一个 `ServeHTTP(w, r)` 方法，所以 `http.Handle` 能接收函数、结构体、任何有这个方法的东西——这是接口小到极致的红利。
3. **mock 编译期检查**：测试文件里写 `var _ UserStore = (*fakeStore)(nil)`，忘了实现某个方法，`go test` 在编译阶段就报错，不用等用例跑起来才发现。
4. **JSON 动态字段**：`var body map[string]any` 先把前端传来的东西整体吃下来，再按 key 断言成具体类型，比定义一堆结构体灵活。
5. **错误分类**：`switch e := err.(type)` 判断是 `*ValidationError` 还是 `*DBError`，决定回 400 还是 500。

## 常见误解（FAQ）

**❌ 误区1："Go 接口也要显式声明 implements"**

Go 没有 implements 这个关键字。方法签名对上了就自动实现，写错一个方法名就等于没实现，而且报错只在赋值那一刻出现。推荐在实现处写 `var _ I = (*T)(nil)` 做编译期断言，把错误提前到编译阶段。

**❌ 误区2："值接收者的方法指针也能调，所以指针和值都能装进接口"**

"能调"和"能装"是两件事。`*T` 的方法集包含值接收者的方法，所以 `*T` 什么都能装；但 `T` 的方法集里**只有值接收者的方法**，指针接收者的方法装不进去，报 `method X has pointer receiver`。

**❌ 误区3："any 是一种特殊类型，跟 interface{} 不一样"**

`any` 是 `interface{}` 的**类型别名**（Go 1.18 引入），不是新类型。`var a any` 和 `var b interface{}` 完全等价，`a == b` 为 true，`[]any` 就是 `[]interface{}`。

**❌ 误区4："接口变量里装的是 nil 指针，所以它等于 nil"**

不等于。接口是（类型, 值）两个字，塞了 nil 指针之后类型字非空，`a == nil` 是 false。想判断里面的指针是不是 nil，得断言出来再看：`if p, ok := a.(*Cat); ok && p == nil`。

**❌ 误区5："类型断言失败会返回零值，不会崩"**

单返回值写法 `v.(T)` 失败直接 panic，只有 `v, ok := x.(T)` 才安全。而且断言到"不可能实现该接口的类型"时编译器就拦了（`impossible type assertion`），连 panic 的机会都没有。

## 一句话总结

Go 的接口没有 implements，方法写全了就算实现；值接收者两边都能装、指针接收者只有指针能装；装了 nil 指针的接口永远不等于 nil——这三句背下来，接口题就答完了。
