## 一句话概括

Go 只有值传递，一个字节都不白送：传 `int` 复制 `int`，传 `struct` 复制整个 `struct`，传指针复制的也只是"地址"那 8 个字节。所以**想让函数改掉调用方的变量，唯一办法是把地址传进去**。

JS 里对象、数组天生就是"引用"，不用写任何符号就能改到同一个对象；但它**没法让函数改掉调用方那个变量本身**——`q = { ... }` 改不了外面的 `o`。

面试一般问三个：「`&` 和 `*` 分别是什么」「Go 是值传递还是引用传递」「Go 的指针和 JS 的引用有什么区别」。第三问最能看出你是真懂还是背的。

## 核心知识点

### 1. `&` 取地址，`*` 顺着地址读写

```go
package main

import "fmt"

func main() {
	x := 10
	p := &x                     // p 的类型是 *int，值是 x 的地址
	fmt.Println(*p)             // 10：顺着地址取值
	*p = 20                     // 顺着地址写值
	fmt.Println(x)              // 20，x 真的变了
	fmt.Printf("%T %v\n", p, p) // *int 0xc0000120a8（每次运行地址不同）
}
```

两个符号、三种用法，别混：

| 写法 | 意思 |
| --- | --- |
| `&x` | 取地址，得到 `*T` |
| `*p` 出现在表达式里 | 解引用，读写那个地址上的值 |
| `*T` 出现在类型里 | "指向 T 的指针"，`*int` / `*User` / `**int` 都行 |

几条固定事实：指针零值是 `nil`；64 位机上指针占 8 字节（`unsafe.Sizeof(p)` 实测 8）；**Go 没有指针运算**，`p + 1` 直接编译不过，报 `invalid operation: p + 1 (mismatched types *int and untyped int)`；指针之间只能比相等，`p1 < p2` 报 `operator < not defined on pointer`。想玩地址加减只能进 `unsafe`，业务代码里不该出现。

### 2. Go 全是值传递，指针是"改得动"的唯一手段

```go
package main

import "fmt"

type User struct {
	Name string
	Age  int
}

func setName(u User)     { u.Name = "改不动" }
func setNamePtr(u *User) { u.Name = "改得动" }

func main() {
	u := User{Name: "旧名字", Age: 18}
	setName(u)
	fmt.Println(u.Name) // 旧名字
	setNamePtr(&u)
	fmt.Println(u.Name) // 改得动
}
```

`setName(u)` 拿到的是 `u` 的完整副本，改副本跟原件没关系——这跟 JS"传对象能改属性"的直觉正好相反。

最容易答错的一层是：**指针本身也是值传递**。函数拿到的是"地址的副本"，所以：

```go
package main

import "fmt"

func reassign(p *int) {
	p = new(int) // 只改了手里这份地址副本
	*p = 999
}

func main() {
	x := 1
	reassign(&x)
	fmt.Println(x) // 1，没变
}
```

想改调用方必须 `*p = ...`（顺着地址写）；`p = ...`（换个地址）只影响函数内部。一份内存、两个指过去的变量——这就是全部玄机。

什么时候该用指针，三句话：

1. **要改**调用方的值；
2. 结构体大，不想整个拷贝（传地址只要 8 字节）；
3. 想表达"这个值可能没有"——nil 指针。

反过来，小结构体、只读参数直接传值更清楚，别到处上指针。

### 3. 和 JS 的引用到底差在哪

先看 JS 的行为（node 实测，两次输出都是 `2`）：

```js
const o = { x: 1 };
const p = o;
p.x = 2;
console.log(o.x); // 2：同一个对象，改属性互相可见

let q = o;
q = { x: 9 };     // 只是让 q 指向新对象
console.log(o.x); // 2：o 没变
```

看出来了吗——**JS 的"引用"也不能重新指向调用方的变量**，`q = { ... }` 只改了 `q` 自己。这跟 Go 里 `p = new(int)` 改不动外面，本质是同一件事。

真正的差别在"默认行为"：

| | Go | JS |
| --- | --- | --- |
| 默认传参 | 全是拷贝（值类型拷值，指针拷地址） | 基本类型拷值，对象/数组传"引用的拷贝" |
| 想改调用方变量 | 传 `&x`，函数里 `*p = ...` | 做不到（只能改对象属性，改不了绑定） |
| 语法 | 显式 `&` / `*` | 完全隐式 |
| 基本类型能否取地址 | 能，`&num` 合法 | 不能，`number` 没有地址可给 |
| 空值 | `nil`，解引用直接 panic | `null` / `undefined`，读属性抛 `TypeError` |

还有几个 Go 特有的"半引用"类型，面试常拿来当陷阱：**slice、map、chan 本身就带引用语义**（内部持有指针）。所以传 slice 进函数能改元素、但改不了长度（长度是切片头里的字段，传的是头的副本）；map 传进去随便改，因为它传的就是同一个底层表。这也是 Go 里"传 map 不用加 `*`"的原因。

### 4. 四个必踩的坑

**坑一：nil 指针解引用。**

```go
package main

import "fmt"

type User struct{ Name string }

func main() {
	var u *User
	fmt.Println(u == nil) // true
	// fmt.Println(u.Name) // panic: runtime error: invalid memory address or nil pointer dereference
	if u != nil {
		fmt.Println(u.Name)
	}
}
```

报错原文就是注释里那行（本机实测）。Go 没有 JS 那种"读 undefined 属性抛 TypeError"的温和版本，这里是 panic，进程直接挂。所以凡是返回 `*T` 的函数，调用方必须判 nil。

**坑二：不是什么东西都能取地址。**

| 写法 | 编译报错（实测，省掉了统一的 `invalid operation: ` 前缀） |
| --- | --- |
| `&m["a"]` | `cannot take address of m["a"] (map index expression of type int)` |
| `&f()` | `cannot take address of f() (value of type int)` |
| `&1` | `cannot take address of 1 (untyped int constant)` |
| `&s[0]`（s 是 string） | `cannot take address of s[0] (value of type byte)` |

规则一句话：**只有"变量"和可寻址的东西（切片元素、数组元素、结构体字段、指针解引用）能取地址**。map 元素不是变量（查表算出来的），函数返回值不是变量，常量更不是。而 `&slice[0]` 合法，改它能改到底层数组。

**坑三：map 里放值，字段改不了；放指针才行。**

```go
package main

import "fmt"

type User struct {
	Name string
	Age  int
}

func main() {
	byVal := map[string]User{"u1": {Name: "旧", Age: 1}}
	// byVal["u1"].Name = "新" // ❌ cannot assign to struct field byVal["u1"].Name in map
	u := byVal["u1"] // 只能整个取出来
	u.Name = "新"
	byVal["u1"] = u // 再整个写回去
	fmt.Println(byVal["u1"].Name) // 新

	byPtr := map[string]*User{"u1": {Name: "旧", Age: 1}}
	byPtr["u1"].Name = "新"       // ✅ 直接改
	fmt.Println(byPtr["u1"].Name) // 新
}
```

map 的 value 不可寻址，所以字段赋值编译不过。要频繁改字段就存 `*User`，代价是每个值单独分配、还要防 nil。

**坑四：指针解决不了浅拷贝。** 结构体里带 slice / map / 指针字段时，`b := a` 只拷贝这些字段的"头"，底层数据还是共享的：

```go
package main

import "fmt"

type Box struct{ Data []int }

func main() {
	a := Box{Data: []int{1, 2, 3}}
	b := a
	b.Data[0] = 999
	fmt.Println(a.Data) // [999 2 3]，a 也变了
}
```

这跟 JS 的浅拷贝（`{ ...obj }`）一模一样，不是 Go 独有的坑；要真隔离就 `slices.Clone` 或老老实实深拷贝。

## 落到项目里长什么样

1. **修改入参**：`func (s *UserService) Update(u *User) error`，service 层几乎全是指针接收者——要改状态，也因为结构体大。
2. **可选字段**：接口里用 `Nickname *string` 区分"没传这个字段"（nil）和"传了空字符串"（指向 `""`），`string` 类型区分不了。对接前端表单时天天遇到。
3. **链表 / 树**：`type Node struct { Next *Node }`，指针是表达"指向另一个节点"的唯一手段，Go 没有 JS 那种自动包装。
4. **避免大对象拷贝**：分页查询返回 `[]*Order`，几十个字段的结构体拷来拷去很浪费；但三五个字段的小结构体用值更省 GC 压力。
5. **和前端对照记**：React 里 `setState({ ...state, a: 1 })` 是"造新对象"，Go 里 `*p = User{...}` 是"原地覆盖"。一个不可变更新、一个原地改，思路正好相反——写 Go 时别带着不可变的执念到处 copy。

## 常见误解（FAQ）

**❌ 误区1："Go 的指针就相当于 JS 的引用"**

方向对了一半。相同的是"通过它改数据，调用方看得见"；不同的是：Go 的指针显式、能对 `int` 这种基本类型用、能重新指向、能是 nil；JS 的引用隐式，你没法"拿到 number 的地址"。

**❌ 误区2："传指针就是引用传递"**

Go **只有值传递**，传指针传的是"地址这个值"的拷贝。证据：函数里 `p = new(int)` 改不动外面的指针本身（实测 `x` 还是 1）。能改到数据，是因为两个地址指向同一块内存，不是因为"引用传递"这个机制。

**❌ 误区3："返回局部变量的地址会变成野指针"**

C 里是错的，Go 里是安全的。`func newUser() *User { u := User{}; return &u }` 完全合法，编译器保证这个 `u` 活到没人引用它为止（需要就放堆上），最后由 GC 回收。这也是 Go 敢让你到处 `return &T{}` 的原因。

**❌ 误区4："nil 指针调用方法一定 panic"**

不一定，看方法有没有碰 receiver。本机实测：`var u *User; u.Kind()` 这种只返回常量的方法能正常跑；一碰字段（`u.Name`）才 panic。所以接口返回 `*T` 时别想当然认为它一定安全。

**❌ 误区5："`*p++` 是让指针往后挪一位"**

那是 C 的直觉。Go 里 `++` 是语句不是表达式，`*p++` 会被解析成 `(*p)++`，效果是把**指向的值加 1**。本机实测：`x := 5; p := &x; *p++` 之后 `x` 是 6，指针一点没动。Go 也不支持指针算术，想挪地址只能进 `unsafe`。

## 一句话总结

Go 里所有参数都是拷贝，`&` 拿地址、`*` 顺着地址读写；想让函数改调用方只能传指针，而指针本身也是值——JS 的隐式引用恰恰相反：能改对象，但改不了调用方的绑定。
