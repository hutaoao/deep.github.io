## 一句话概括

Go 的函数比 JS 简单——**没有重载、没有默认参数、没有 this**，但多了三样 JS 没有的东西：多返回值、可变参数、`defer`。

面试官问函数，翻来覆去就这三问：

- 为什么 Go 的函数都返回 `(结果, error)`？error 为什么必须放最后？
- `func sum(nums ...int)` 和 `sum(slice...)` 到底怎么回事？会不会复制？
- `defer` 和 `return` 哪个先执行？为什么命名返回值能被 defer 改掉？

第三个是重点，几乎每场 Go 面试都会问一遍。

## 核心知识点

### 1. 多返回值：error 永远最后一个

```go
package main

import (
	"errors"
	"fmt"
)

func divide(a, b float64) (float64, error) {
	if b == 0 {
		return 0, errors.New("divide by zero")
	}
	return a / b, nil
}

func main() {
	v, err := divide(10, 2)
	fmt.Println(v, err) // 5 <nil>

	v, err = divide(10, 0)
	fmt.Println(v, err) // 0 divide by zero

	// 多返回值可以整包当参数，但只能是"唯一实参"
	fmt.Println(divide(12, 3)) // 4 <nil>

	// v := divide(10, 2) // 编译错：assignment mismatch: 1 variable but divide returns 2 values
}
```

三条惯例，照着写就对了：

1. **error 放最后一个返回值**。这是全生态的约定，不是你随便排的——所有 `if err != nil` 的调用方都默认它是最后一个。
2. **出错时，其他返回值一律是零值，调用方不许用**。所以 `divide(10, 0)` 返回的 `0` 不是"结果接近 0"，只是占位。
3. **不要用返回值表示"没找到"**。`(User, error)` 里，查不到用 `error`（比如 `sql.ErrNoRows` 或自定义 `ErrNotFound`），不要返回 `nil, nil` 让调用方猜。

顺带一个语法点：**Go 没有"返回 1 个值也行、2 个值也行"的重载**。想要"有时候要 error 有时候不要"，只能写两个函数（`MustParse` / `Parse` 这种命名在标准库里到处都是）。

还有一个容易被追问的写法——**命名返回值**：

```go
package main

import "fmt"

// x、y 在函数开始就按零值初始化了，return 后面什么都不写就是返回它们
func split(sum int) (x, y int) {
	x = sum * 4 / 9
	y = sum - x
	return // 裸返回
}

func main() {
	fmt.Println(split(17)) // 7 10
}
```

命名返回值本身只是"给返回值起个名字"，好处是签名自带文档（`(width, height int)` 比 `(int, int)` 清楚）。但它真正的用途是下一节那个 defer 陷阱——**只有命名返回值，defer 才改得动最终结果。**

### 2. 可变参数：本质是一个切片

```go
package main

import "fmt"

func sum(nums ...int) int {
	total := 0
	for _, n := range nums {
		total += n
	}
	return total
}

func bump(nums ...int) {
	if len(nums) > 0 {
		nums[0] = 999 // 改的是调用方的底层数组
	}
}

func showNil(nums ...int) {
	fmt.Println(nums == nil, len(nums)) // true 0
}

func main() {
	fmt.Println(sum())        // 0      ← 一个都不传，nums 是 nil 切片
	fmt.Println(sum(1, 2, 3)) // 6

	s := []int{1, 2, 3}
	fmt.Println(sum(s...)) // 6      ← s... 把切片摊开
	bump(s...)
	fmt.Println(s) // [999 2 3]  ← 没复制，共享底层数组

	showNil()

	// fmt.Println(sum(s, 4)) // 编译错：cannot use s (variable of type []int) as int value in argument to sum
}
```

四个点：

1. **`...int` 在函数体里就是 `[]int`**，`len`、`range`、下标全都能用。
2. **一个都不传时它是 `nil`**，不是空切片。所以 `len(nums) == 0` 成立，但 `nums == nil` 也成立——判空用 `len` 更稳。
3. **`s...` 不复制**。它把切片头直接传进去，函数里改元素会改到调用方（实测 `[999 2 3]`）。想隔离就进函数先 `slices.Clone`。
4. **`s...` 只能配切片，不能和散装参数混着写**。`sum(s, 4)` 直接编译不过，必须 `sum(append(s, 4)...)` 或者干脆不摊开。

再补一条限制：**可变参数必须是最后一个参数**，而且**一个函数只能有一个**。`func f(a ...int, b string)` 是非法的。

跟前端对照：JS 的 `...args` 拿到的是**新数组**，改它不影响调用方；Go 的 `s...` 是**共享底层数组**。这是同一个语法符号、完全相反的语义，转语言时最容易踩。

### 3. defer 三条铁律（重点）

先给结论：**`return` 不是一条原子指令**。它分三步——给返回值赋值 → 执行所有 defer（LIFO）→ 真正返回。defer 就插在中间那一步。

```go
package main

import "fmt"

// ① 命名返回值：defer 改得动最终结果
func f1() (result int) {
	defer func() { result++ }()
	return 0
}

// ② defer 改的是普通局部变量 t，返回值早就被复制走了
func f2() (r int) {
	t := 5
	defer func() { t = t + 5 }()
	return t
}

// ③ defer 带参数，参数在注册那一刻就求值了
func f3() (r int) {
	defer func(r int) { r = r + 5 }(r)
	return 1
}

// ④ 连命名返回值都没有，defer 里怎么改都影响不到外面
func f4() int {
	x := 1
	defer func() { x++ }()
	return x
}

func main() {
	fmt.Println(f1(), f2(), f3(), f4()) // 1 5 1 1
}
```

四个函数四个 1/5，逐个拆：

- **f1 返回 1**：`return 0` 先把 0 赋给 `result`，然后 defer 跑 `result++`，`result` 变成 1，最后带着 1 返回。**注意不是 0。**
- **f2 返回 5**：`return t` 把 5 复制给 `r`，defer 里改的 `t` 已经和返回值没关系了。
- **f3 返回 1**：`defer func(r int){...}(r)` 里的 `r` 是**参数**，注册时就被求值成 0（那时 `r` 还是零值），函数体里的 `r = r + 5` 改的是这个参数副本，跟返回值 `r` 毫无关系。
- **f4 返回 1**：`return x` 把 1 复制到匿名的返回值槽位，之后 defer 改 `x` 也没用。

所以三条铁律：

1. **多个 defer 是栈：后注册的先执行（LIFO）**。资源按"先申请后释放"的顺序自然展开，这跟栈帧对称，也是它被设计成 LIFO 的全部理由。
2. **defer 后面跟的参数，在 `defer` 那一行就求值了**，不是执行时。想拿到"执行时的最新值"就必须用闭包直接引用变量，不能传参。
3. **只有命名返回值能被 defer 改掉**。因为命名返回值的变量就是那个"返回值槽位"本身，而普通 `return x` 是复制一份过去。

一句话记法：**`return x` = 先赋值给返回值槽位，再跑 defer，再 RET。命名返回值让 defer 摸得到槽位，普通返回值摸不到。**

### 4. defer 的实战用法与三个坑

```go
package main

import (
	"fmt"
	"os"
)

// recover 必须写在"被 defer 的直接函数"里
func safeDiv(a, b int) (result int) {
	defer func() {
		if r := recover(); r != nil {
			fmt.Println("recover:", r)
			result = -1 // 靠命名返回值把错误码带出去
		}
	}()
	return a / b
}

func main() {
	fmt.Println(safeDiv(10, 2)) // 5
	fmt.Println(safeDiv(10, 0)) // recover: runtime error: integer divide by zero → -1

	defer fmt.Println("这一句不会打印")
	fmt.Println("准备退出")
	os.Exit(0) // defer 全部跳过
}
```

实测输出里 **"这一句不会打印"** 真的没打印——`os.Exit` 直接终止进程，defer 一个都不跑。这是线上最难查的一类"资源没释放"：明明写了 `defer f.Close()`，程序退出时文件句柄还是漏了。

三个高频坑：

1. **`recover` 只在被 defer 的函数里直接调用才有效**。写成 `defer recover()` 或者在 defer 里再调一个普通函数让它 recover，都接不到。而且它只能接**当前 goroutine** 的 panic，子 goroutine 崩了照样带崩整个进程。
2. **循环里 `defer` 会一直累积**到函数返回才执行。一个 for 循环打开 1 万个文件各写一句 `defer f.Close()`，就是 1 万个句柄同时开着，大概率 `too many open files`。正确做法是包一层小函数，让 defer 随函数返回就执行。
3. **`defer` 里的闭包捕获的是变量本身，不是当时的快照**。`defer func(){ fmt.Println(i) }()` 这种写法：Go 1.21 及更早三个 defer 共享同一个 `i`，全打印 3；Go 1.22 起每次迭代是新变量，打印 2 1 0。而 `defer fmt.Println(i)`（把 i 当参数传）因为参数在注册时就求值了，两个版本都打印 2 1 0——这正是"参数注册时求值"那条规则在起作用。

## 落到项目里长什么样

1. **`defer` 紧跟资源获取那一行**：`f, err := os.Open(...)` 之后立刻 `defer f.Close()`，别等到函数末尾再补——中间一改代码就可能漏。
2. **写文件要 `defer` 里检查错误**：`defer f.Close()` 的返回值被丢弃了，缓冲写失败根本发现不了。要么显式 `err = f.Close()`，要么用 `defer func() { if e := f.Close(); e != nil && err == nil { err = e } }()`。
3. **HTTP handler 里必须 `defer recover`**：一个 panic 就能让整个请求链路 500 且没有日志。Gin 的 `gin.Recovery()` 中间件干的就是这件事，自己写裸 `net/http` 时别忘。
4. **可变参数适合"默认值"的替代方案**：Go 没有默认参数，标准做法是 `WithTimeout(d)` 这类 functional options，或者 `...Option`。写库接口时比堆一长串参数好维护。
5. **多返回值别超过三个**。`(a, b, c, d, error)` 这种签名调用方一定记错顺序，改成返回一个 struct。

跟前端对照：JS 的 `try/finally` 和 Go 的 `defer` 是一个思路，但有两个差别——JS 的 `finally` 每个函数只有一个，Go 可以有任意多个且逆序执行；JS 的 `return` 也是先算值再跑 finally，所以 `finally` 里改局部变量同样改不动返回值，这一点两边一致。

## 常见误解（FAQ）

**❌ 误区1："defer 是在 return 之后执行的"**

不准确。`return x` 拆开是"赋值给返回值 + 执行 defer + RET"，defer 夹在赋值和真正返回之间。所以它才改得动命名返回值——如果真在 return 之后，那就什么都改不了了。

**❌ 误区2："命名返回值 + defer 一定能改掉返回值"**

得看 defer 怎么改。`defer func(){ result++ }()` 能改（闭包捕获了 result 变量）；`defer func(r int){ r++ }(result)` 改不动（参数是注册时的副本）。区别就在"传参"还是"闭包引用"。

**❌ 误区3："recover 写在 defer 里就能接住 panic"**

只有 `defer func(){ recover() }()` 这种**在 deferred 函数体内直接调用**才有效。写成 `defer recover()` 无效——那样 `recover` 自己成了被 defer 调用的函数，而它只有在"被 defer 的函数内部直接调用"时才生效，实测 panic 照样往上传。更别说跨 goroutine，子 goroutine panic 没人接就是整个进程崩。

**❌ 误区4："`sum(s...)` 会把切片复制一份再传进去"**

不复制。传的就是切片头，底层数组是同一块，实测函数里改 `nums[0]`，调用方的 `s[0]` 跟着变。要隔离自己 `slices.Clone`。

**❌ 误区5："可变参数不传就是空切片"**

是 nil 切片。`sum()` 里 `nums == nil` 为 `true`、`len(nums)` 为 0。判空统一用 `len(x) == 0`，别用 `== nil`，否则"传了个空切片"和"没传"会被区别对待。

**❌ 误区6："Go 支持函数重载和默认参数"**

都不支持，这是刻意的设计取舍：只有一个调用约定、不用做重载决议，编译快、可读性好。要"可选参数"就用可变参数、functional options 或配置 struct。

## 一句话总结

**Go 函数的三件事一句话说完：error 永远是最后一个返回值、`s...` 传的是切片头不复制、`return` 是"赋值 → defer → 返回"三步走——所以只有命名返回值能被 defer 改掉，记住这一句，defer 题就通关了。**
