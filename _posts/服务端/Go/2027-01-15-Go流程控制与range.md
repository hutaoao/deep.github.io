## 一句话概括

JS 里 `for`、`while`、`do-while`、`forEach`、`map` 一大堆循环写法，Go 就一个关键字 `for`，靠"省略哪一段"变出另外两种形态。

面试问流程控制，一般就四个问题：

- Go 没有 while，怎么写循环？
- switch 要不要写 break？`fallthrough` 是干嘛的？
- `range` 遍历 slice / map / string / channel 分别返回什么？
- `range` 有哪些坑？

前三个是概念题，第四个是筛人题。下面逐个说。

## 核心知识点

### 1. for 是唯一的循环，三种写法靠省略

```go
package main

import "fmt"

func main() {
	sum := 0
	for i := 0; i < 3; i++ { // 三段式
		sum += i
	}

	n := 3
	for n > 0 { // 只留条件 → 就是 while
		n--
	}

	for { // 全省 → 无限循环
		break
	}

	fmt.Println(sum, n) // 3 0
}
```

口诀：**`for 初始化; 条件; 后置` 三段全写是三段式，只留条件就是 while，全省就是死循环。** Go 里没有 `while` 关键字，也不需要。

循环里跳出来用 `break` / `continue`，但**嵌套时它们只管自己那一层**。想跨层就用标签：

```go
func main() {
outer: // 标签写在 for 前面
	for i := 0; i < 3; i++ {
		for j := 0; j < 3; j++ {
			if j == 1 {
				continue outer // 跳过内层剩下的，直接进下一次外层
			}
			if i == 2 {
				break outer // 两层一起跳出
			}
			fmt.Println("inner", i, j)
		}
	}
}
```

实测输出只有两行 `inner 0 0`、`inner 1 0`。标签是 Go 里少见的"看起来像 goto 但不算坏味道"的语法，处理二维遍历特别好用。

顺带记一个新语法：**Go 1.22 起 `range` 可以直接跟整数**，`for i := range 3` 就是 `i = 0,1,2`，不用再写 `for i := 0; i < 3; i++`。

### 2. if 能带初始化语句，switch 默认不穿透

`if` 的三条硬规则：条件**不写括号**（写了也能编译，`gofmt` 会帮你删掉）、**必须布尔值**（`if 1` 直接报 `non-boolean condition in if statement`）、大括号**不能省**。另外它支持一条前置语句：

```go
func main() {
	if v := 10; v > 5 {
		fmt.Println("v 只在 if 内部可见", v)
	}
	// fmt.Println(v) // ❌ undefined: v
}
```

这个写法在 Go 里是标配，因为错误处理长这样：`if err := do(); err != nil { ... }`，把 `err` 关在 `if` 的作用域里，不污染外层。

`switch` 和 C / JS 差别最大的是两点：**每个 case 自带 break**，以及 **case 可以是任意表达式**。

```go
func main() {
	for _, s := range []int{1, 2, 3} {
		switch s {
		case 1:
			fmt.Println("one")
		case 2, 3: // 一个 case 多个值
			fmt.Println("two or three")
		default:
			fmt.Println("other")
		}
	}
}
```

输出 `one` / `two or three` / `two or three`——没有穿透，也不需要写 `break`。想穿透必须显式 `fallthrough`：

```go
func main() {
	switch 1 {
	case 1:
		fmt.Println("a")
		fallthrough
	case 2:
		fmt.Println("b") // 条件不匹配也被执行
	}
}
```

输出 `a`、`b`。`fallthrough` 的三条硬规则（都亲手试过）：

| 规则 | 违反的后果 |
| --- | --- |
| 只能出现在 case 块**最后一条非空语句** | `fallthrough statement out of place` |
| **不能**出现在最后一个 case | `cannot fallthrough final case in switch` |
| 无条件跳到**相邻的下一个** case，不做判断 | —— |

网上大量文章说"fallthrough 不能用于 default"，这是错的。实测：`fallthrough` **跳到** `default` 合法（输出 `a` 再 `default`），写在 `default` 块末尾再跳去下一个 `case` 也合法（输出 `default` 再 `two`）。真正的限制只有上面那两条：不能是最后一条语句之后的"孤儿"，不能从最后一个分支往外跳。

还有一个超实用的写法——**不写表达式就是 `switch true`**，可以当更整齐的 if-else 链：

```go
func main() {
	score := 85
	switch {
	case score >= 90:
		fmt.Println("A")
	case score >= 60:
		fmt.Println("B")
	default:
		fmt.Println("C")
	}
}
```

最后补一个容易搞混的点：**在 switch 里写 `break` 只跳出 switch，不跳出外层循环；写 `continue` 却是作用于循环的**（因为 switch 本身不能被 continue）。实测 `for` 里套 `switch { case ...: continue }`，`continue` 直接进了下一轮循环。

### 3. range 的五种形态：每种返回值都不一样

这是面试问得最细的地方。`range` 能遍历的东西有五种，返回值各不相同：

```go
func main() {
	list := []int{1, 2, 3}
	for i, v := range list { // 索引, 值
		fmt.Print(i, v, " ")
	}

	m := map[string]int{"a": 1}
	for k, v := range m { // 键, 值
		fmt.Print(k, v)
	}

	for i, r := range "你好" { // 字节索引, rune
		fmt.Print(i, r, " ")
	}

	ch := make(chan int, 2)
	ch <- 10
	ch <- 20
	close(ch)
	for v := range ch { // 只有值
		fmt.Print(v, " ")
	}

	for i := range 3 { // 整数（Go 1.22+），只有"值"
		fmt.Print(i, " ")
	}
}
```

对照表（面试可以直接背这个）：

| 遍历对象 | 第一个变量 | 第二个变量 | 备注 |
| --- | --- | --- | --- |
| 数组 / 切片 | 索引 `int` | 元素**副本** | 单变量时拿到的是索引 |
| map | 键 | 值 | 顺序**随机** |
| string | **字节**索引 | `rune` | 中文一个字占 3 字节 |
| channel | 值 | —— | channel 关闭后循环结束 |
| 整数 n（1.22+） | `0..n-1` | —— | `for range 3` 也能不要变量 |

两个最常被问错的细节：

1. **单变量写法拿到的是索引，不是值**。`for i := range list` 里 `i` 是 `int` 索引；想要值必须写 `for _, v := range list`。而 `for i := range 3` 里 `i` 又是"值"（0、1、2），因为它根本没有索引这回事。
2. **string 的索引是字节偏移**。`for i, r := range "你好"` 打印出来是 `i=0 r=你`、`i=3 r=好`，不是 0 和 1。这就是"`len("你好")` 等于 6"的同一个根因：Go 的 string 底层是 UTF-8 字节序列。

### 4. range 的四个坑，全是面试原题

**坑一：range 后面的表达式只求值一次。**

```go
func main() {
	list := []int{1, 2, 3}
	for i, v := range list {
		if i == 0 {
			list = append(list, 99)
		}
		fmt.Println(i, v, len(list))
	}
}
```

实测输出三行，`len(list)` 已经是 4，但循环只跑了 3 轮、`v` 永远是 1/2/3。原因：`range list` 在**进入循环前**把切片头（指针 + 长度 + 容量）复制了一份，之后 `list` 变量指向哪都跟循环无关。所以"边遍历边 append 能遍历到新元素吗"的答案是**不能**——哪怕没有触发扩容、新元素就写在同一块内存上，循环用的那个长度也已经固定了。

**坑二：第二个变量是值拷贝，改它不影响原数据。**

```go
func main() {
	items := []int{1, 2, 3}
	for _, v := range items {
		v *= 10 // 改的是副本
	}
	fmt.Println(items) // [1 2 3]
}
```

要改就得用索引：`for i := range items { items[i] *= 10 }`。这条和 JS 的 `forEach((v) => v*10)` 一致，但很多人会误以为 Go 的 `v` 是引用。

**坑三：map 遍历顺序是随机的，而且每次运行都不一样。**

同一份代码连跑三次，实测拿到三种顺序：`d a b c` / `a b c d` / `b c d a`。这不是 bug，是 Go 故意的——**防止你依赖顺序写出"本地能跑线上偶发失败"的代码**。要稳定顺序就把 key 取出来排序再遍历。

**坑四：`&v` 的地址问题（Go 1.22 起已修）。**

Go 1.22 之前，`for _, v := range` 的 `v` 在整个循环里是同一个变量，把 `&v` 存进切片会得到一堆指向同一处的指针。1.22 起每次迭代新建一个 `v`，这个问题消失了——本机 1.27 实测，三个 `&v` 是三个不同地址：

```go
func main() {
	list := []int{1, 2, 3}
	var ptrs []*int
	for _, v := range list {
		ptrs = append(ptrs, &v)
	}
	fmt.Println(ptrs[0] == ptrs[1], ptrs[1] == ptrs[2]) // false false
}
```

注意前提：这个行为**由 `go.mod` 里的 `go` 版本决定**，写 `go 1.22` 及以上才生效，老项目没改 `go` 指令就还是旧行为。这块涉及闭包捕获，后面单独一篇讲，这里先记住"**1.22 之后不用担心了**"。

## 落到项目里长什么样

1. **处理列表数据**：`for _, item := range list` 是日常主力；只要索引就写 `for i := range list`。`for i, _ := range` 也能跑（`go vet` 不报错，试过了），但多出来的 `_` 纯属噪音。
2. **批量带下标修改**：更新库存、改状态这类一定要 `for i := range list { list[i].X = ... }`，用 `v` 改是无效的——这个 bug 上线后表现为"接口返回成功但数据没变"，排查极费时间。
3. **map 组装响应体**：遍历 map 拼 JSON，别指望顺序稳定；需要固定字段顺序就定义结构体，`encoding/json` 对结构体是按字段声明顺序输出的。
4. **带超时的重试**：`for i := 0; i < 3; i++` 配 `if err == nil { break }`，比递归清爽；退出条件一定要写 `<` 不写 `<=`，避开溢出回绕。
5. **状态机式判断**：`switch` 不写表达式 + `case cond:` 比一串 `else if` 好读，也是 Go 里处理"多条件分流"的惯用写法（比如按分数段返回等级）。

## 常见误解（FAQ）

**❌ 误区1："Go 里没有 while，所以循环不灵活"**

`for 条件 {}` 就是 while，`for {}` 就是死循环，`for 初始化; 条件; 后置` 就是三段式。一个关键字覆盖三种形态，比记三个关键字更省心。

**❌ 误区2："switch 每个 case 后面要写 break"**

不用写，Go 默认不穿透，case 执行完自动结束。反过来，想穿透得显式写 `fallthrough`。而在 switch 里写的 `break` 只是"提前结束这个 switch"，不会跳出外层循环。

**❌ 误区3："`fallthrough` 不能用于 default"**

错。实测 `case 1: ... fallthrough` 跳到 `default` 是合法的，`default` 块末尾 `fallthrough` 到下一个 `case` 也合法。真正的两条限制是：必须是 case 块最后一条非空语句（否则 `fallthrough statement out of place`）、不能出现在最后一个分支（否则 `cannot fallthrough final case in switch`）。

**❌ 误区4："`for i := range list` 里的 `i` 是元素值"**

是索引。想要值写 `for _, v := range list`。但 `for i := range 3`（整数）里 `i` 是 0、1、2，因为没有索引可给。

**❌ 误区5："遍历 map 的顺序至少是插入顺序"**

完全随机，而且每次运行都变。Go 规范明确说 map 的迭代顺序未指定，运行时还专门加了随机起点。要顺序就自己排序。

**❌ 误区6："range 遍历时改切片，循环次数会跟着变"**

不会。`range` 的表达式在循环开始前求值一次，切片的长度被固定住了。追加元素可能让底层数组搬家，但循环里那个"旧切片头"看不见新元素。

## 一句话总结

Go 用一个 `for` 干掉所有循环，用"默认不穿透"干掉漏写 break 的老 bug，用五种 `range` 返回值考你到底有没有真写过——记住"单变量拿索引、value 是副本、map 顺序随机、表达式只算一次"这四句，流程控制题就过关了。
