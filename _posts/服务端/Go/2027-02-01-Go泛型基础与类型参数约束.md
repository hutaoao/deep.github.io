## 一句话概括

Go 1.18 加了泛型，语法上就是 TS 的 `<T>` 换成了 `[T any]`：**把类型当参数传进去，让一份代码适配多种类型，同时保留编译期检查**。

但有 TS 经验的人第一次写 Go 泛型，十个有九个会卡在同一个地方——**"我的 T 为什么不能 `==`、不能 `len`、不能取属性？"**

原因很简单：TS 的 `T` 默认什么都能干（`any` 兜底），Go 的 `T` 能干什么是**约束（constraint）说了算**。约束里没写的操作，编译器一个都不让你做。

面试问泛型，基本就问这么几件事：怎么声明、约束怎么写、和 TS / interface{} 有什么不一样——外加一条"哪些事干不了"。下面按这几条拆。

## 核心知识点

### 1. 类型参数：方括号里写"类型变量"

```go
package main

import "fmt"

// T、U 就是类型参数，any 是最松的约束（等价于 interface{}）
func Map[T, U any](s []T, f func(T) U) []U {
	out := make([]U, 0, len(s))
	for _, v := range s {
		out = append(out, f(v))
	}
	return out
}

func main() {
	nums := []int{1, 2, 3}

	// ✅ 平时都靠推导：从 []int 和 func(int) string 反推出 T=int、U=string
	strs := Map(nums, func(n int) string { return fmt.Sprint(n * 10) })
	fmt.Println(strs) // [10 20 30]

	// 也能显式指定，但一般不写
	fmt.Println(Map[int, string](nums, func(n int) string { return "x" })) // [x x x]
}
```

几个要点：

- **方括号不是随便选的**。Go 里 `<` `>` 是小于大于号，`f(a<b, c>d)` 这种写法会解析歧义，所以官方用了 `[]`。
- **类型参数写在函数名后面、参数列表前面**，位置和 TS 一样（`function map<T, U>`）。
- **泛型也能挂到结构体上**，而且用起来最舒服：

```go
package main

import "fmt"

type Stack[T any] struct {
	items []T
}

func (s *Stack[T]) Push(v T) { s.items = append(s.items, v) }

func (s *Stack[T]) Pop() (T, bool) {
	var zero T // T 的零值，只能这么拿
	if len(s.items) == 0 {
		return zero, false
	}
	v := s.items[len(s.items)-1]
	s.items = s.items[:len(s.items)-1]
	return v, true
}

func main() {
	s := &Stack[int]{}
	s.Push(1)
	s.Push(2)
	fmt.Println(s.Pop()) // 2 true

	str := &Stack[string]{}
	str.Push("a")
	fmt.Println(str.Pop()) // a true
}
```

注意 `Stack[T]` 里的方法也要带 `[T]`——**类型参数属于类型本身，接收者必须写成 `*Stack[T]`**。

### 2. 约束：不是"限制"，是"允许清单"

这是 Go 泛型最反直觉的地方。约束不是"你不能干什么"，而是"**你能干什么**"——约束里声明了什么，函数体里就能用什么；没声明的，一行都写不出来。

| 约束写法 | 允许的类型 | 函数体里能做什么 |
| --- | --- | --- |
| `any` | 所有类型 | 只能赋值、传参、转成 `any` |
| `comparable` | 支持 `==` `!=` 的类型 | 可以 `==`，可以当 map 的 key |
| `int \| float64` | 只有这两个 | 可以 `+ - * /` |
| `~int` | 底层是 int 的所有类型（含自定义类型） | 可以算术运算 |
| `interface{ String() string }` | 实现了该方法的类型 | 可以调 `v.String()` |

最容易被追问的是 `~`。看这段：

```go
package main

import "fmt"

type Age int

// 只认 int 本身
type IntOnly interface{ int }

// 底层是 int 的都要
type IntLike interface{ ~int }

func DoubleExact[T IntOnly](v T) T { return v * 2 }
func DoubleLike[T IntLike](v T) T  { return v * 2 }

func main() {
	var a Age = 20
	fmt.Println(DoubleLike(a)) // ✅ 40，~int 认自定义类型

	// ❌ 编译不过，实测报错：
	// Age does not satisfy IntOnly (possibly missing ~ for int in IntOnly)
	// fmt.Println(DoubleExact(a))
}
```

**记住这一条：加了 `~` 才算"底层类型"，不加就是"只认这一个类型"。** 报错里那句 `possibly missing ~` 就是编译器在提示你。

约束本身就是一个接口，所以**方法约束和类型约束是同一套语法**：

```go
package main

import (
	"fmt"
	"strings"
)

// 约束 = 一个方法集合
type Stringer interface {
	String() string
}

func Join[T Stringer](items []T) string {
	parts := make([]string, len(items))
	for i, v := range items {
		parts[i] = v.String() // 约束里有 String()，所以能调
	}
	return strings.Join(parts, ",")
}

type User struct{ Name string }

func (u User) String() string { return "user:" + u.Name }

func main() {
	u1 := User{Name: "a"}
	u2 := User{Name: "b"}
	fmt.Println(Join([]User{u1, u2})) // user:a,user:b
}
```

再记三条实跑出来的报错，面试说得出原文就显得很扎实：

```text
[]int does not satisfy comparable           // 切片没有 ==，不能当 comparable
invalid operation: a == b (incomparable types in type set)   // T 只约束了 any 却写了 ==
invalid map key type T (missing comparable constraint)       // map[T]V 的 K 忘了约束
```

### 3. 泛型体里的三条硬边界

**边界一：零值只能 `var zero T`。**

```go
package main

import "fmt"

func Zero[T any]() T {
	var z T // ✅ 唯一稳妥的写法
	return z
}

func ZeroByNew[T any]() T {
	return *new(T) // ✅ 也行，new 出一个 T 的指针再解引用
}

func main() {
	fmt.Println(Zero[int](), Zero[string]() == "", ZeroByNew[*int]() == nil) // 0 true true
}
```

为什么不能写 `if v == nil`？因为 `T` 可能是 `int`，和 nil 比没意义，编译器直接拦：

```text
invalid operation: v == nil (mismatched types T and untyped nil)
```

**边界二：约束没声明的操作，一律不许写。**

```text
// ❌ 这样写编译不过：
// invalid argument: v (variable of type T constrained by any) for built-in len
func Len[T any](v T) int { return len(v) }
```

```go
package main

import "fmt"

// ✅ 想让 len 能用，就得把类型集合写出来
func Len[T string | []byte](v T) int { return len(v) }

func main() {
	// 字符串算字节数，两个汉字 6 字节
	fmt.Println(Len("你好"))
	fmt.Println(Len([]byte("你好")))
}
```

同理，`v.Field`、`v + 1`、`v[0]` 全都得先有约束。**Go 的泛型不做运行时检查，所以编译器必须能在编译期就确定"这个操作对 T 的所有候选类型都成立"。**

**边界三：不能对 T 做类型断言，要先转 `any`。**

```go
package main

import "fmt"

func Kind[T any](v T) string {
	switch any(v).(type) { // ✅ 先转 any 才能 type switch
	case int:
		return "int"
	case string:
		return "string"
	default:
		return "其他"
	}
}

func main() {
	fmt.Println(Kind(1), Kind("s"), Kind(1.5)) // int string 其他
}
```

直接写 `v.(string)` 会报 `cannot use type assertion on type parameter value v`。道理还是上面那条：泛型是编译期的事，类型断言是运行期的事，两者不在一个层面。

顺便记一个版本点：**Go 1.27 之前方法不能有自己的类型参数**（类型参数只能挂在类型上），1.27 起官方放开了（release notes 原文：a method declaration may declare its own type parameters），但**接口的方法至今仍不允许带类型参数，接口方法也不能由泛型方法实现**。这条是很好的加分项，答出来说明你跟进版本。

### 4. 和 TS 泛型对照表

| | TS | Go |
| --- | --- | --- |
| 声明 | `function map<T, U>(...)` | `func Map[T, U any](...)` |
| 约束 | `T extends number` | `[T Number]`，接口即约束 |
| 类型推导 | 有，还能从返回值倒推 | 有，主要从参数推 |
| 运行时 | **完全擦除**，产物里没有 T | **实例化**，运行时就是具体类型 |
| 体内能用什么 | 约束里有的属性/方法 | 约束里有的操作，多一个都不行 |
| 泛型值 | 类型层面，值层面照样是普通对象 | 同样只在类型层面，没有"泛型变量" |

表里"运行时"那一行是面试常问的："Go 泛型和 TS 泛型的运行时差别？"

答：**TS 编译完类型全被擦掉，跑起来还是 JS 那套动态类型；Go 是编译期按具体类型实例化，`Stack[int]` 和 `Stack[string]` 是两个真类型，运行时不需要任何断言**。所以 Go 泛型没有"类型信息丢失"的问题，也正因为要实例化，才不能像 TS 那样在体内随便对 T 做操作。

那什么时候**不该**用泛型？三句话：

1. 只有一两种类型 → 直接写两份，比泛型好读。
2. 要装一堆异构数据 → 用 `any` + 断言或接口，泛型反而不合适。
3. 类型之间行为差异大 → 用接口，多态比泛型自然。

Go 官方那篇泛型指南的建议是：**先按具体类型写，重复到第三遍再抽泛型**。

## 落到项目里长什么样

1. **统一响应体**：`type Response[T any] struct { Code int; Msg string; Data T }`，一个结构适配所有接口，前端 TS 那边写 `ApiResponse<T>` 就能对上，两边类型完全镜像。
2. **分页**：`type Page[T any] struct { List []T; Total int; Page int }`，`Page[User]`、`Page[Order]` 不用各写一份。
3. **通用查询工具**：`func Pluck[T, K any](items []T, key func(T) K) []K`，从订单列表里抽 id、从用户列表里抽名字，一个函数覆盖。
4. **缓存/对象池**：`type Cache[K comparable, V any] struct { m map[K]V }`，key 用 `comparable` 约束，value 随便什么类型。
5. **和前端 TS 的对照**：前端那个 `function useFetch<T>(url: string): Promise<T>`，在同构项目里对应后端 `func Get[T any](url string) (T, error)`——一个思路，只是 Go 要把 `T` 的约束显式写出来。

## 常见误解（FAQ）

**❌ 误区1："`any` 约束下什么都能干，跟 TS 的泛型一样自由"**

正相反，`any` 是**最松的类型限制**，但同时也是**最弱的操作能力**：只能赋值、传参、转成 `any`。想 `==` 得用 `comparable`，想 `len` 得写 `string | []byte`，想加得写数字联合。很多人把 `any` 当成"百无禁忌"，一写 `a == b` 就撞上 `incomparable types in type set`。

**❌ 误区2："`~int` 和 `int` 是一回事"**

差一个自定义类型。`type Age int` 不满足 `interface{ int }`，但满足 `interface{ ~int }`。业务里 ID、金额这种自定义类型满地都是，忘了 `~` 就是一片编译错误，报错原文还会贴心提示 `possibly missing ~`。

**❌ 误区3："泛型方法想加就加"**

Go 1.27 之前不行，只能把类型参数写在类型上（`type Stack[T]`）。1.27 起普通方法可以有自己的类型参数了，但**接口里的方法永远不行**，而且接口方法不能被泛型方法实现。面试被问"Go 泛型有什么限制"，这条比背语法有用。

**❌ 误区4："Go 泛型也像 TS 一样运行时被擦除"**

不是。Go 是**编译期实例化**，`Stack[int]` 和 `Stack[string]` 是两个真正独立的类型，运行时类型信息完整、不需要断言。TS 的擦除是"编译完就没有 T 了"，Go 的实例化是"编译完 T 变成了具体类型"，方向正好相反。

**❌ 误区5："用了泛型性能就更好"**

泛型主要买的是**类型安全和少写重复代码**，不是性能。它确实省掉了 `interface{}` 那层装箱和断言，但别指望数量级提升。真正该用不用泛型的判断标准是"逻辑一样、类型不同、且要编译期检查"，不是"听说泛型快"。

## 一句话总结

Go 泛型就三句话：`[T any]` 是类型参数、约束是**允许清单**不是限制、体内只能干约束里写过的事——零值用 `var zero T`，断言先转 `any`，加了 `~` 才认自定义类型。
