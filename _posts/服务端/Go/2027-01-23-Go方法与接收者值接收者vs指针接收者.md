## 一句话概括

Go 的面向对象只有一句话：**方法 = 带接收者参数的函数**，没有 class、没有继承、没有 this。

值接收者和指针接收者的区别，面试的标准答法是三层：

1. **改不改得动**：值接收者拿到的是副本，改完就扔；指针接收者改的是原件；
2. **方法集**：`T` 只拥有值接收者方法，`*T` 才拥有全部方法——这决定了**接口能不能赋值**；
3. **自动取地址有边界**：`u.Method()` 编译器会帮你写成 `(&u).Method()`，但前提是 `u` **可寻址**。

前两条是面试必答，第三条是真实项目里踩坑最多的。

## 核心知识点

### 1. 方法就是"绑了接收者的函数"

```go
package main

import "fmt"

type Counter struct {
	N int
}

// 普通函数：第一个参数显式写
func incFunc(c Counter) { c.N++ }

// 方法：接收者写在 func 和名字中间
func (c Counter) IncByValue() { c.N++ }  // 值接收者
func (c *Counter) IncByPtr()  { c.N++ }  // 指针接收者

func main() {
	c := Counter{}
	c.IncByValue()
	fmt.Println(c.N) // 0 ← 改的是副本
	c.IncByPtr()
	fmt.Println(c.N) // 1 ← 改的是原件
}
```

**为什么 `IncByValue` 改不动？** 因为 `c.IncByValue()` 等价于 `IncByValue(c)`，参数是值传递，传进去的是整个结构体的一份拷贝。

这也解释了另一件事：**方法和函数没有本质区别**，`c.IncByPtr()` 就是 `(&c).IncByPtr()`，Go 把接收者当第一个参数塞进去了而已。

### 2. 值接收者的两个副作用：大结构体复制、slice 字段半生效

先看一个容易被面试官抓住的细节：

```go
package main

import "fmt"

type List struct {
	Items []int
}

func (l List) SetFirst(v int) { l.Items[0] = v } // 改元素 → 生效
func (l List) Add(v int)      { l.Items = append(l.Items, v) } // 改 header → 不生效
func (l *List) AddPtr(v int)  { l.Items = append(l.Items, v) }

func main() {
	l := List{Items: []int{1, 2}}
	l.SetFirst(9)
	fmt.Println(l.Items) // [9 2] ← 居然生效了
	l.Add(3)
	fmt.Println(l.Items) // [9 2] ← 没加上
	l.AddPtr(3)
	fmt.Println(l.Items) // [9 2 3]
}
```

原因在切片本身的三个字段：拷贝出来的是**切片头**（指针、len、cap），底层的数组还是同一个。所以改元素改的是共享的数组，生效；`append` 改的是副本自己的 len，外面看不到。

**一句话记住：值接收者能改"指针指向的东西"，改不了"结构体自己的字段"。**

第二个副作用是性能。值接收者每次调用都整块复制：

```go
type Big struct {
	Data [1024]byte // 1KB
}

func (b Big) Size() int  { return len(b.Data) }  // 每次调用复制 1KB
func (b *Big) Size2() int { return len(b.Data) } // 只复制 8 字节的指针
```

调用 100 万次，前者就是 1GB 的内存搬运。Go wiki 给了一条判断标准：**把结构体的所有字段当成函数参数列出来，如果你觉得"这参数太多了"，那它也太大，不该用值接收者。**

### 3. 方法集：决定谁能实现接口

这是接收者最容易考倒人的地方，也是唯一需要背规则的点。

Go 规范里写得很清楚：

- **类型 `T` 的方法集**：只包含接收者为 `T` 的方法；
- **类型 `*T` 的方法集**：包含接收者为 `T` 和 `*T` 的**全部**方法。

翻译成人话：**`*T` 的方法集是 `T` 的超集，指针"多"拥有指针接收者的方法。**

接口是隐式实现的，判据就是"方法集有没有覆盖接口要求的方法"。所以：

```go
package main

import "fmt"

type Notifier interface{ Notify() }

type User struct{ Name string }

func (u *User) Notify() { fmt.Println("notify", u.Name) } // 指针接收者

type Sender interface{ Send() }

type Mail struct{ Addr string }

func (m Mail) Send() { fmt.Println("send", m.Addr) } // 值接收者

func main() {
	var n Notifier = &User{Name: "a"} // ✅ 必须是指针
	n.Notify()

	// ❌ var n2 Notifier = User{Name: "a"}
	// 报错：cannot use User{…} (value of struct type User) as Notifier value
	//       in variable declaration: User does not implement Notifier
	//       (method Notify has pointer receiver)

	// 值接收者就宽松：值和指针都算实现
	var s1 Sender = Mail{Addr: "x"}
	var s2 Sender = &Mail{Addr: "y"}
	s1.Send()
	s2.Send()
}
```

**这就是"混用接收者"的危害**：只要类型里有一个方法用了指针接收者，这个类型就只能以 `*T` 的身份去满足接口，值类型 `T` 直接被踢出局。

嵌入结构体也遵循同一套规则（Go 规范原文）：

- 嵌入 `T`：`S` 和 `*S` 都提升 `T` 的方法，但 `*T` 的方法只有 `*S` 有；
- 嵌入 `*T`：`S` 和 `*S` 都有 `T` 和 `*T` 的全部方法。

```go
type Base struct{ Name string }

func (b *Base) Speak() {}

type Outer struct{ Base }     // 嵌值
type OuterPtr struct{ *Base } // 嵌指针

// ✅ var s Speaker = &Outer{}
// ❌ var s Speaker = Outer{}
//    Outer does not implement Speaker (method Speak has pointer receiver)
// ✅ var s Speaker = OuterPtr{&Base{}}
```

### 4. 自动取地址有边界：只有"可寻址"的值才行

写 `u.Rename()` 能调指针方法，是因为编译器偷偷帮你加了 `&`。**但只对可寻址的值生效**——变量可寻址，函数返回值、map 元素、常量都不行。

```go
package main

import "fmt"

type User struct{ Name string }

func (u *User) Rename(n string) { u.Name = n }

type V struct{ Name string }

func (v V) String() string { return "V:" + v.Name } // 值接收者

type P struct{ Name string }

func (p *P) String() string { return "P:" + p.Name } // 指针接收者

func newUser() User { return User{Name: "tmp"} }

func main() {
	u := User{Name: "a"}
	u.Rename("b") // 等价于 (&u).Rename("b")
	fmt.Println(u.Name) // b

	// ❌ 函数返回值不可寻址：
	// newUser().Rename("x")
	// 报错：cannot call pointer method Rename on User

	// ❌ map 元素也不可寻址：
	// m := map[string]User{"a": {Name: "a"}}
	// m["a"].Rename("b")
	// 报错：cannot call pointer method Rename on User

	// String() 是最典型的"接收者影响行为"的例子
	fmt.Println(V{Name: "x"})  // V:x  ← 值和指针都命中
	fmt.Println(P{Name: "x"})  // {x}   ← 没命中，走了默认打印
	fmt.Println(&P{Name: "x"}) // P:x
}
```

**`String()` 那三行特别值得记**：`fmt.Println` 收到的参数是 `any`，`P` 装进 `any` 之后是一个不可寻址的值，方法集里没有 `String()`，所以打印出来是 `{x}`。想让它命中，要么用指针接收者 + 传指针，要么干脆全用值接收者。

顺带回答"怎么选"这个问题，Go wiki 的官方口径可以直接背：

- 需要改接收者 → **必须**指针；
- 结构体里有 `sync.Mutex` 之类的同步字段 → **必须**指针（拷贝锁等于拷贝出一把新锁）；
- 大结构体 / 大数组 → 指针，省一次整块复制；
- **map、func、chan 不要用指针接收者**；slice 只要不 reslice、不重新分配，也不要用指针；
- 小且天然是值类型的东西（`time.Time`、`int`、`string`）→ 值接收者；
- **同一个类型的所有方法要么全用指针、要么全用值，不要混**；
- 拿不准就用指针。

## 落到项目里长什么样

1. **Service 层统一指针接收者**：`func (s *UserService) Get(id int) (*User, error)`。里面有 DB 连接、日志器、配置，都是"全进程一份"的东西，复制一份毫无意义。
2. **DTO / 请求体用值接收者**：`func (r LoginReq) Validate() error`。请求参数天然是快照，方法也不该改它，值语义最清楚。
3. **`sync.Mutex` 一定用指针**：`func (c *Cache) Set(...)` 里 `c.mu.Lock()`，如果接收者是值，锁的是副本，等于没锁——这个 bug 一到并发就炸，而且极难复现。

```go
package main

import (
	"fmt"
	"sync"
)

type Cache struct {
	mu sync.Mutex
	m  map[string]string
}

// ✅ 指针接收者，锁的是同一把锁
func (c *Cache) Set(k, v string) {
	c.mu.Lock()
	defer c.mu.Unlock()
	if c.m == nil {
		c.m = make(map[string]string)
	}
	c.m[k] = v
}

func main() {
	c := &Cache{}
	c.Set("a", "1")
	c.Set("b", "2")
	fmt.Println(len(c.m)) // 2
}
```

4. **`Error()` / `String()` 跟着类型走**：如果类型本身是以 `*T` 形式到处传的（比如自定义 error），那 `Error()` 也必须是 `*T` 接收者，否则 `errors.As` 拿到的值永远走默认格式。
5. **和前端对照**：JS 的 class 方法里的 `this` 是运行时绑定的，一解构就丢；Go 的接收者是编译期写死的，`u.Rename` 这个表达式不存在"丢 this"的问题，但也因此没有 `bind` 这种补救手段。

## 常见误解（FAQ）

**❌ 误区1："值接收者性能更好，因为不用解引用"**

反了。值接收者每次调用都复制整个结构体，大结构体上这是纯浪费。wiki 的原话是"值接收者可能减少堆分配（栈上复制），但**不要没做 profile 就为这个理由选值接收者**"。

**❌ 误区2："指针接收者的方法，值类型也能调，所以没区别"**

调得动是因为编译器自动加了 `&`，**但接口赋值不会帮你加**。`var n Notifier = User{}` 直接编译失败，只有 `&User{}` 才行。调得动 ≠ 实现得了接口，这是两件事。

**❌ 误区3："同一个类型里混用值/指针接收者没关系"**

有关系。只要有一个方法用了指针接收者，`T` 的方法集就不完整，`T` 再也不能满足任何要求那个方法的接口。而且代码读起来也乱——wiki 明确说不要混。

**❌ 误区4："slice、map 当字段时也应该用指针接收者"**

wiki 反着写的：**map、func、chan 不要用指针接收者**，slice 只要不 reslice / 不重新分配也不用。因为它们本身就是"描述符"，复制一下很便宜，用指针反而多一层间接。

**❌ 误区5："值接收者绝对不能改数据"**

要看改的是什么。改**字段**（`u.Name = x`）不生效；改**字段指向的内容**（`u.Items[0] = x`、`u.Ptr.Field = x`、`u.Map[k] = v`）生效，因为副本和原件共享同一块底层数据。至于 `append`、`重新赋值 map`，那改的是副本自己的头部，不生效。

## 一句话总结

值接收者拿副本、指针接收者拿原件；`T` 的方法集只有值接收者方法，`*T` 才是全集——所以「能不能改数据」是小事，「能不能实现接口」才是要命的那条。
